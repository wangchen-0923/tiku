## 一、4 项决策落定

### 决策 1 · 公共题库：教师上传 → 平台管理员审核 → 管理员可管理

**好消息：三样东西已经有了，不用新建。**

| 已有 | 位置 | 用法 |
|---|---|---|
| `Role.PLATFORM_ADMIN` | `apps/accounts/models.py:23` | 审核人身份，不新增角色 |
| `QuestionStatus.PENDING_REVIEW` | `apps/common/constants.py:26` | 提交后进待审，不进组卷 |
| `Question.approve()` / `reject()` | `apps/questionbank/models.py:477-491` | 带 `reviewed_by` / `reviewed_at` / `reason` |
| `question/<pk>/approve/` | `apps/questionbank/urls.py:58` | 端点已有，加权限与作用域即可 |

**只需新增一个维度：`QuestionBank`（`kind = PRIVATE | PUBLIC`）。** 现有 `QuestionGroup` 是材料题组，与题库无关，别复用。

**归属已定：系统 - 机构 - 用户三层。** 现状有一处缺口——`OrgType` 只有 `SCHOOL` / `TRAINING`（`org/models.py:30`），**没有平台层**，而 `question.org_id` 是 `NOT NULL`。所以：

- 新增 `OrgType.PLATFORM`（迁移层面只是 choices 变化，DB 无 CHECK 约束，`AlterField` 为 no-op）；
- 建一行平台机构（如「知否平台」），承载**系统层资产**：公共题库、公共知识库、平台级提示词模板；
- 公共题的 `org_id` 指向平台行 → **不动现有 `NOT NULL` 约束**，历史数据零影响。

**一个必须避开的操作**：`admin` 这个 `PLATFORM_ADMIN` 账号当前 `org_id=1`（挂在测试学校上），与模型注释「平台管理员为空」不符。**不要顺手把它改成平台机构**——改完他立刻看不到 org=1 的任何数据。平台管理员的公共库权限走 `role=PLATFORM_ADMIN` 判定，不依赖 `org_id` 归属。

**代价**：比原方案（跨机构只读）多 +2 人日，用于审核队列、驳回理由、下架；再加 0.5 人日做 `OrgType.PLATFORM` 与平台行初始化（并入 U11）。

### 决策 2 · 公式导出走 B（Node + 无头浏览器）

现有导出是 reportlab（`apps/paper/render.py`）。**关键发现**：`paper/urls.py:43` 的 `export/?layout=1` 已经能单独返回排版 JSON —— 说明「排版」与「渲染」已经解耦，Node 服务只要吃这份 JSON，不用碰 Django 的排版逻辑。

**代价**：+2.5 人日；部署多一个常驻服务。**必须与盘点 P4「部署未验收」合并做**，否则线上仍然只有纸面方案。

### 决策 3 · 组卷引用公共题 = 先下载到私有库

这条决策**简化了 M4**：组卷取题路径完全不用改（仍只抽本机构私有题），省掉「跨机构联合查询 + 权限判定」约 1.5 人日。

**引入了新问题：副本漂移。** 公共题被修订后，私有副本不会跟着变。处理办法见 §3.3——记录来源与版本，只提示不自动同步。

### 决策 4 · 积分系统 + 自定义 API Key

新增 6 人日。有两个可以直接接上的现成资产：

**① 计量数据已经全了。** `AICallLog`（`apps/ai/models.py:230`）已有 `user` / `org` / `task` / `input_tokens` / `output_tokens` / `cost_yuan` / `idempotency_key`。积分不需要自己再记一遍消耗，只需在流水里引用 `ai_call_log.id`。

**② 一段死代码正好可以激活。** `routing.py:281` 的 `budget_left_yuan` 参数用来「预算不足时跳过贵模型」，但全仓**没有任何调用方传它**；配套的配置项 `ai.monthly_budget_yuan` 默认 `0.0` 且无人读取（`apps/common/config.py:145`）。把积分余额喂进去，预算降级才第一次真正生效。

**加密不新造。** `apps/ai/masking/crypto.py` 已有 AES-GCM 的 `encrypt_field` / `decrypt_field`，密钥来自 `ZF_PII_KEK`（未设时由 `SECRET_KEY` 派生并告警）。

**但不要复用同一个 KEK。** 理由：PII 密钥轮换会让全部教师的 API Key 同时失效，两类数据的访问审计对象也不同。做法是同一个模块、不同的 key 用途（新增 `ZF_SECRET_KEK`）。

## 三、四条决策的实现方案

### 3.1 公共题库

**模型**

```
QuestionBank
  id
  kind              # PRIVATE | PUBLIC
  org_id            # 三层归属：PRIVATE → 所属学校；PUBLIC → 平台机构行（type=PLATFORM）
  name / description
  status            # ACTIVE | ARCHIVED
  created_by
```

`Question` 加 `bank_id`（先 nullable → 回填 → 再考虑收紧），并保留 `org_id` 不动。

**三层归属的判定规则**（写死在 `QuestionBank` 上，不靠调用方自觉）：

| 层 | 取哪个 org | 数据可见范围 |
|---|---|---|
| 系统 | 平台机构行（`type=PLATFORM`） | 全平台，需 `PLATFORM_ADMIN` 审核后可见 |
| 机构 | 学校 org | 仅本机构 |
| 用户 | 不单独建库，靠 `created_by` 过滤 | 本机构内按创建人筛选 |

**权限矩阵**

| 动作 | 教师 | 机构管理员 | 平台管理员 |
|---|---|---|---|
| 私有库增删改 | 自己的 | 本机构 | — |
| 提交到公共库 | ✅ | ✅ | ✅ |
| 审核公共题 | ❌ | ❌ | ✅ |
| 编辑已发布公共题 | ❌ | ❌ | ✅ |
| 下架 / 删除公共题 | ❌ | ❌ | ✅ |
| 下载到私有库 | ✅ | ✅ | ✅ |

**查询收口——这是全项目风险最高的一处改动。**

`for_org()` 是「唯一的正常取数入口」（`apps/common/managers.py:151`，缺 `org_id` 直接抛 `OrgScopeRequired`）。**绝对不要改基类的 `for_org`**，那会同时改变 57 张表里所有实体的语义。

正确做法：只在 `Question` 自己的 QuerySet 子类里覆写。

```
QuestionQuerySet.for_org(org_id)
  → Q(org_id=org_id)                          # 本机构全部（含草稿、待审）
    | Q(bank__kind=PUBLIC, status=APPROVED)    # 公共库仅"已审核"可见
```

配套一条**可机器校验的约束**：CI 里加 grep 断言，除 `questionbank` 外任何模块不得直接对 `Question` 写 `.filter(org_id=...)`。否则半年后一定会有人绕过收口点。

### 3.2 公式导出 B

**链路**

```
DB
 └→ paper/layout.py 生成排版 JSON      ← 已存在，export/?layout=1 已验证可返回
     └→ POST /render（Node 服务，内网）
         └→ HTML（KaTeX SSR，服务端渲染成静态节点）
             └→ Puppeteer → PDF（A4/双栏/页眉页脚）
                 └→ Django 接收 bytes → 存储 → 签名 URL
```

**接口契约**

```
POST /render
  { layout: {...}, paperSize: "A4", dpi: 300 }  →  application/pdf
  Header: X-Render-Token（内网共享密钥，不走用户 JWT）
超时 30s；单次并发上限 2；浏览器实例常驻复用（冷启动约 1s）
```

**三个必须解决的技术点**

1. **中文字体**：镜像内装 Noto Sans SC / Noto Serif SC，并显式写进 CSS `font-family`，否则无头浏览器渲染出方框。
2. **公式字体离线**：KaTeX 的 woff2 必须内嵌 base64，不能指望 CDN——校内网络常无外网。
3. **回退**：Node 服务不可用时回落 reportlab（公式退化为文本或图片），并在导出结果里标记 `render_engine=LEGACY`，避免「同一份卷子两次导出长得不一样还查不出原因」。

**部署影响**：`docker-compose` 多一个服务，内存约 600MB（Chromium）。所以 U20 必须与 U36 一起验收。

### 3.3 下载式引用

**复制什么、重置什么**

| 字段 | 处理 |
|---|---|
| 题干 / 选项 / 答案 / 解析 / 知识点 / 配图 | 复制 |
| `status` | 重置为 `DRAFT`（下载后需自己审核才能组卷） |
| `created_by` / `org_id` | 改为下载者 / 本机构 |
| `source_question_id` / `source_version` | 新增，指向公共题及其版本 |
| `source_ref` | 记公共库标识，便于统计 |

**漂移处理**：私有副本列表对「有更新版本的来源题」显示一个浅色角标「公共库已更新至 v3」，点击可查看 diff 或重新下载。**不自动同步**——老师可能已经改过这道题。

**两个副作用要提前告知**

1. **相似题去重会误报**：`question/<pk>/similar/` 会命中自己下载的副本。需在相似判定里排除「同一 `source_question_id` 的副本」。
2. **题量统计会虚高**：报表需按 `source_question_id IS NULL` 区分原创与副本，否则「本机构题库 3000 题」里有大量外来重复。

### 3.4 积分系统 + 自定义 API Key

**数据模型**

```
points_account          -- 一人一账户
  user_id (unique), balance, frozen
  period        # 'YYYY-MM'，月配额懒重置用（见下方发放口径）
  updated_at
  # balance 为整数积分，避免小数累积误差

points_ledger           -- 只追加，不修改
  account_id, delta, balance_after
  type        # GRANT | PREAUTH | SETTLE | REFUND | ADJUST | EXPIRE
  ref_type    # AI_CALL | ADMIN_GRANT | MONTHLY_QUOTA | RESOURCE_DOWNLOAD
  ref_id
  note, created_by, created_at
  unique(account_id, ref_type, ref_id, type)   -- ★ 幂等键，防重复扣

user_ai_credential
  user_id, provider, base_url
  key_cipher   # AES-GCM 密文（复用 ai/masking/crypto.py，换 KEK）
  key_mask     # sk-****3f2a，仅用于回显
  status, last_used_at, last_test_ok_at
```

**积分发放（已定：月配额制，不做自助充值）**

| 项 | 口径 |
|---|---|
| 发放主体 | 机构管理员给本机构教师配月额度；平台管理员给机构配总额度 |
| 周期 | **按自然月重置**，不累加、不结转（避免余额无限膨胀，也让成本可预测） |
| 存放 | 机构总额度落 `org.quota_config`（字段已存在），教师额度落 `points_account` |
| 调整 | 支持管理员当月加减（写 `ADJUST` 流水，留操作人与理由） |
| 充值 | **一期不做**，不引入支付 |

**月重置的实现方式**：不做定时任务改余额，而是给账户加 `period`（`YYYY-MM`）字段——读余额时若 `period` 不是当前月，则视为全新配额，首次写操作时把 `period` 滚到当前月并写一条 `MONTHLY_QUOTA` 流水。这样不依赖 Celery（正好避开盘点 P2「worker 未运行」这个坑），也不会出现「1 号凌晨定时任务失败导致全校老师不能用 AI」。

**扣费时序（最关键的 5 步）**

```
1. 估算：复用 routing.py 已有估算逻辑得 est_points
2. 预扣：事务内 SELECT ... FOR UPDATE 扣 balance，写 PREAUTH
3. 调用 AI（外部 HTTP，事务外）
4. 成功：按 ai_call_log.cost_yuan 折算实际积分 → SETTLE 多退少补
5. 失败/超时/被拒绝：RELEASE 全额退回
```

**为什么必须预扣而不是后扣**：AI 调用可能跑 30s，并发 10 个请求若都后扣，余额会被透支成负数。预扣把超支挡在发出请求之前。

**为什么必须 `SELECT ... FOR UPDATE`**：`balance` 是热点行，用「读-算-写」在两个并发请求下必然丢更新。

**不扣积分的场景**：教师使用自己的 API Key 时，`credential_source=USER`，成本记 0 元、积分记 0 分。但仍受 `apps/ai/limits.py` 三层令牌桶约束——否则自带 Key 就等于绕过全局限流。

**密钥解析优先级**

```
user_ai_credential（本人配置，启用且测试通过）
  → org.ai_config（机构统一采购）
    → ZF_AI_API_KEY（平台环境变量）
```

降级必须留痕：现有 `AIResult.degraded_from` 扩展一个 `credential_source` 字段。否则「这次为什么用了平台 Key 花了钱」无法解释。

**安全红线**

- Key 写入后**永不返回原文**，只回显 `key_mask`；
- 更新 Key 只能整体覆盖，不支持「读取后再编辑」；
- 访问凭证表的操作写 `AuditLog`（`apps/audit` 已有表，缺端点 U29 一并补）；
- 解密只在调用瞬间发生，不写日志、不进 `request_payload`。

**对账**：每日跑一次，`SUM(ai_call_log.cost_yuan WHERE credential_source=PLATFORM)` 折算积分 vs `SUM(ledger.delta WHERE type IN (PREAUTH,SETTLE,REFUND))`，差值 > 1 元告警。没有对账的积分系统，半年后一定出现「有人余额是负的」而没人说得清。

#### U02 · 兜底不是从零做，原系统已有两级

`pick_for_slot()` 本来就有「P1 变式 → P2 近期未做 → P3 其余 → 降级①放宽难度

#### 设计要点 1 · 课程编码「锁在数据上」，不是锁在状态上

章 / 任务 / 知识点的编码都是 `<course.code>-C01-T01-K01` 拼出来的。
所以 `code` 的可改性**取决于这门课有没有下级数据**，而不是「是不是已发布」：

- 空课程可以随便改编码（新建时打错字是最常见的情况）；
- 一旦长出章 / 知识点 / 题 / 卷，改编码就是 409 `KNOWLEDGE.CODE_LOCKED`，
  并列出被什么卡住（`data.references`），提示改成「改名」或「新建课程」。

删除同理：`Chapter` / `KnowledgeNode` 的外键是 `CASCADE`，但**软删不触发级联**。
只把课程打上 `deleted_at` 会把整棵树与挂在树上的题留成孤儿（组卷时还抽得到）。
所以删除要求**全空**，有引用就 409 `KNOWLEDGE.IN_USE`。
想下线但保留数据→ `PATCH {"status":"ARCHIVED"}`，两个动作分开给。

#### 设计要点 2 · 移动知识点只改 4 个冗余列，不动 `code`

`KnowledgeNode` 上有 4 个派生列：`course` / `subject` / `grade_band` / `path`。
只改 `task`（外键）会让「按课程统计知识点」「按课程码抽题」在跨课程移动后
返回**旧课程**的数据，而界面上看起来一切正常。所以移动时四列一起改，
`task_knowledge.is_primary` 与 `chapter_knowledge` 一起搬。

`code` **不重算**：它已经被题目关联、被老师抄进教案。移动后编码里的 `T01`
与位置不符是**刻意接受的**——编码是稳定标识，不是位置描述。
想改编码请显式传 `code`，并接受它与位置不符。

#### 设计要点 3 · 6 张待办卡的数字必须「可核对」

首页写「待仲裁 5 张」，点进去列表 6 条，老师从此不信首页任何数字。

#### 缺陷 7 · 建知识点用「数量 + 1」生成编码，删/移之后必然撞车

`create_node()` 原来用 `count() + 1` 当 `K` 序号。知识点被删或**移动走**之后
数量减少而剩下的编码没变，于是新节点算出**已被占用**的编号，直接 400「编码已存在」。
实测撞法：t1 下原有 K01/K02，K01 移到 t2 后 `count=1`，新建节点算出 K02，与仍在 t1 的 K02 撞。
已改为「取该任务下已用的最大 K 序号 + 1」，再兜一层避让。

#### 缺陷 8 · 序列化器把未声明字段**静默丢掉**

DRF 的 `to_internal_value()` 只遍历自己声明的字段，请求体里多出来的键
不报错、直接消失。于是 `PATCH {"name":"新名","org_id":2}` 会返回 200「已更新」，
而 `org_id` 根本没到服务层——老师以为改了机构，其实没改。

同一机制在这个仓库里已经害过一次（`EntryCreateSerializer` 漏声明 `node_ids`，
导致多知识点条目静默只挂一个）。这次新增 `_StrictFieldsMixin`：
**多传的键就是 400**，并列出可用字段。`org_id` / `deleted_at` 这类
「能绕过删除与租户隔离」的字段因此彻底关死。

#### 缺陷 9 · 切片之后 `count()` 得到的是 `min(limit, total)`

`ScanCardSelector.review_queue()` 内部 `[:limit]` 切过。首页要「一共多少张卡」
就得 `.count()`，而在切片上 count 永远是 `min(200, total)`——首页会**永远显示 200**。
拆成 `review_queue_qs()`（条件）+ `review_queue()`（截断）两层，
后者行为不变，首页用前者计数。这类「看起来能算、其实算错」的地方最难发现。

#### 设计要点 1 · 收口的真正难点不是 SQL，是 **Manager 遮蔽 QuerySet**

`for_org()` 覆写在 `QuestionQuerySet` 上**不会生效**：

```python
QuestionManager = OrgScopedManager.from_queryset(QuestionQuerySet)
```

`Manager.from_queryset()` 只复制「基类上没有同名属性」的方法
（Django `_get_queryset_methods`）。而 `OrgScopedManager` **自带** `for_org`
（`filter(org_id=...)`），于是：

- QuerySet 里的覆写被**静默忽略**；
- `Question.objects.for_org(x)` 仍然走基类那版，双轨可见性根本没生效。

**形态极坏**：没有报错、没有警告，`usable_for_paper()` 照常工作，
唯一可观察的差异是「公共题看不见」——看起来像「公共库里没题」。
所以 `QuestionManager` 里必须显式写一行转调。

★ 39 处 `Question.objects.for_org(...)` 全部走 Manager，所以这一行决定全站。

#### 设计要点 2 · 放开读之后**必须**同步收紧写

`for_org()` 放开公共题后，`for_org(1).filter(pk=公共题id)` **能查到**那道题
（它本来就该被看到）。于是任何学校的老师都能调 `PATCH /questions/<公共题id>/`
去改别人提交、平台已审核的题。

修法是**读路径与写路径分别取数**：写操作一律走
`QuestionService._must_get()`（内含 `private_only()`），命中公共题时返回
409 `QUESTION_BANK.INVALID_STATE` 并提示「请先下载到本校私有库」。
共 5 处写取数 + `explain_service` / `tagging` / `ai.services` 一并收紧。

#### 设计要点 3 · 浏览口径与组卷口径必须分开

- `for_org()`：本院全部 + 公共已审 → **题库页/搜题/补标队列看得见**
- `usable_for_paper()`：再叠 `private_only()` → **组卷池只有本校私有题**

决策 3 定的是「引用公共题 = 先下载到私有库」。若组卷池也放开公共题，
卷面上不会显示来源，等于绕过「下载副本 → 本校审核」这条追溯链。

#### 设计要点 4 · 跨机构字段一个都不能照抄

公共题的 `course` / `task` / `question_knowledge` / `question_image.asset`
**全都指向来源机构**：

| 字段 | 照抄的后果 | 处理 |
|---|---|---|
| `course` / `task` | 副本挂在别的机构的课程上，本校永远抽不到它 | 下载时**必填**本校课程，`task` 可选 |
| 知识点 | `node_id` 跨机构无意义 | 提交时记 `source_node_codes`，下载时按 `code` 重映射（映射不上的列出来） |
| 配图 | `media.Asset` 按机构签发签名 URL，跨机构引用 = 绕过媒体授权 | **不复制**；带图提交需显式 `drop_figures=true`，并记 `dropped_figures` |
| 题组 | 材料题的题干在机构资产 `QuestionGroup` 上 | 小题一律拒绝单独提交 |

#### 设计要点 1 · 库里存 **TeX 原文**，不存 KaTeX 产物

`$…$` / `$$…$$` 原样入库，渲染在展示层做。三条理由：

| 若存 KaTeX HTML | 后果 |
|---|---|
| 过 `sanitize_html`（nh3） | `class="katex"` 被白名单洗掉 → 公式退化成乱序字形 |
| 老师要改一个分子 | 得从 `<span class="mord">…</span>` 里反向还原，实际不可编辑 |
| 导出要给 Puppeteer / Word | 两者都要 TeX 源，HTML 没人能反向解析 |

★ 代价是「读的时候要扫」：所以扫描器必须**三处同构** ——
`web/src/utils/math.ts:scanMath` / `server/apps/common/mathtext.py:find_math_spans` /
`render-service/src/math.js:scanMath`。任何一处放宽，同一道题在三端就是三种断句。

#### 设计要点 2 · 行内 `$…$` 的误判防护只有一条规则

老师写「价格 `$5 到 $10`」是常态，不做防护全站都是公式。判据：

- 内含反斜杠 → **是**公式（`$\frac{1}{2}$`）
- 含 CJK 且无反斜杠 → **不是**（`$5 到 $10`）
- 跨行 → 不是（未闭合就退回字面文本，不吞掉半篇文档）

★ 违反「同构」的代价在这里最刺眼：前端判成文本、后端判成公式，
预览是「价格 $5 到 $10」，导出的 PDF 上是 `5到10` 被提成数学式。

#### 设计要点 3 · `$a<b$` 必须在清洗前**挖出来**

HTML5 解析器见到 `<b` 就当标签开始，`$` 被吞进标签名 —— 而解析器**不报错**，
这一行的后半句静默消失。所以 `sanitize_html` 的顺序被固定为：

```
mask_math(原文) → nh3 清洗 → unmask_math(占位符放回)
```

占位符 `ZFMLKMASK{:04d}X` 是纯字母数字，nh3 不会动它。
`paper/textutil.html_to_text` 同理（先掩码、再剥标签、再放回），
否则「`$x<y$` 的题」在摘要里会变成「`$x` 的题」。

#### 设计要点 4 · 排版宽度按**渲染宽度**算，不按源码字符数

`\frac{1}{2}` 有 12 个字符，实际只占 **0.75em**。按源码计数会把它算成 6 个字宽，
于是 4 个短公式选项明明能排 4 列，却被判成 2 列。

`tex_width_em()` 用 em 表估算（`_CMD_EM` / `_GREEK_EM` / `_CHAR_EM`），原则是
**宁可估宽**：多留白不难看，公式压到下一栏外面才是废卷。

★ 折行时公式是**不可分割原子**：`split_atoms()` 让 `$…$` 整段进出，
`wrap_text_lines()` 到原子边界才换行。不做这件事的典型症状是
「`\frac{1}{2}$` 被切到下一行，上一行只剩一个 `$`」——`$` 数量成奇数，
预览层直接退化成纯文本。

#### 设计要点 5 · `math_render` 双档，且**不进 `layout_config`**

| 档 | 谁用 | 公式形态 |
|---|---|---|
| `tex` | 预览 / Node 渲染 | 保留 `$…$`，交给 KaTeX |
| `plain` | reportlab / Word | `\frac{1}{2}`→`1/2`、`x^{2}`→`x²`、`\sqrt{3}`→`√3`、`30^{\circ}`→`30°` |

`plan_layout(..., math_render=...)` 是**函数参数**，不是配置项。
`layout_config` 会经 `preview_layout_json` 出给客户端，若把 `math_render` 放进去，
等于让前端能决定分页 —— 这是排版层的底线，客户端只能调字号栏数，不能调「公式算不算宽度」。

#### 设计要点 6 · 渲染服务是**弱依赖**，不是链路中继

```
export_pdf → 有公式？→ 是 → render_node.is_enabled()？
                              ├─ 是 → POST /render（超时 35s）
                              │        ├─ 200 → 用返回的 PDF
                              │        └─ 失败 → mark_unavailable(reason) 熔断 120s
                              └─ 否 → 落 plain 档 → reportlab
```

三条守则：

1. **熔断 120s**：服务挂了不白等 35 秒 × 每份卷子。第一次失败就短路，后面直接回退。
2. **回退要留痕但不打扰人**：`PAPER.FORMULA_DEGRADED`，`blocking: False`。
   老师看到的是「导出成功，公式已降级为文本」，不是「导出失败」。
3. **无公式的卷子完全不触碰渲染服务**：`layout_has_math()` 先扫一遍，
   90% 的卷子不会走到这条路 —— 否则渲染服务重启一次，全站导出都慢一拍。

#### 设计要点 7 · 鉴权用**共享密钥**，不是用户 JWT

`X-Render-Token` 从 `RENDER_SERVICE_TOKEN` 读，`timingSafeEqual` 比对。
渲染服务是内网机器人，它不认识「老师」这个角色；拿用户 JWT 过去只会多一层耦合，
而一旦要让 Puppeteer 也具备用户身份，就得把 JWT 塞进页面 —— 那才是真风险。

★ **缺 `RENDER_TOKEN` 且没有 `RENDER_ALLOW_INSECURE=1` 时进程直接 `exit(1)`**。
「配置漏了就静默裸奔」这件事必须在启动时炸掉，不能等到第一次被扫。

#### 设计要点 8 · 字体是这条链路的**唯一线上风险**

本地一切正常、线上满纸方框 —— 差别只在镜像里有没有 `fonts-noto-cjk`。
所以：

- `Dockerfile` 装 `fonts-noto-cjk` + `fonts-noto-cjk-extra`；
- `fonts.js` 把 20 个 KaTeX woff2 内嵌成 data URI（正则剔掉 woff/ttf 两档，
  否则 `leftover_relative_urls` 不为 0，Chromium 会去请求不存在的相对路径）；
- `GET /health` 直接暴露 `{embedded_fonts, leftover_relative_urls, ok}`；
- 渲染前 `document.fonts.ready` 必须 await，否则首字可能用 fallback 落地。

★ **U36 必须复核**：真导一份含公式的卷子，确认线上 `/health` 的 `fonts.ok: true`。
这条不能靠「本地跑通了」推。

#### 缺陷 14 · Puppeteer 23 的 `page.pdf()` 返回 `Uint8Array` 而非 `Buffer`

自检里断言 PDF 魔术字 `%PDF-`，得到 `37,80,68,70,45,…` —— `.toString()` 把字节数组
按逗号拼了。**不报错、不抛异常**，只是「PDF 看起来格式不对」。
修法：`const buf = Buffer.from(raw)`。任何 `typeof buf === 'object'` 就当 Buffer 用，
在 Node 里是错的假设。

#### 缺陷 15 · `v-html` 静态检查会把 HTML 注释算成代码

`StudentAnswerView.vue` 里有一行注释「★★ 走 `MathText` 而不是 `v-html`：…」，

#### 缺陷 16 · 一个抽屉 8 个输入框 = 8 条工具条

`MathInput` 最初的写法是每个输入框自带一条工具条。建题抽屉里题干/选项/解析
一共 8 个框，屏幕上叠了 8 条，视觉上完全没法用。

改成**整页一条共享工具条 + 活动目标注册表**：
`mathInsert.ts` 用 `shallowRef<MathTarget|null>` 记「当前是哪个框在编辑」，
`MathToolbar` 只认这个 ref；输入框 `focus` 注册、`blur` 清除；
`toolbar="popover"` 时才自带局部工具条（组卷页大题标题那种一屏一个的场景）。

★ 工具条按钮必须 `@mousedown.prevent`：`click` 永远发生在 `blur` **之后**，
用 `click` 的话点按钮瞬间焦点已经丢了，插入会落到空气里。

#### 缺陷 17 · 受控组件的 `setSelectionRange` 会被框架重置

`emitValue(v, caret)` 里如果直接 `el.setSelectionRange(caret, caret)`，
Vue 会在同一个 tick 之后的 patch 里把 `value` 写回输入框，光标跳回末尾。
必须 `nextTick()` 之后再设。这个坑只在「选中内容 + 点片段」时暴露：
插入的 `\frac{§}{}` 光标应该停在 `§` 上，实测停在整串末尾。

#### 缺陷 18 · `section.title?: string` 是可选字段

`PaperComposeView.vue(444,17) TS2322: Type 'string | undefined' is not assignable to type 'string'`。
`MathInput` 的 `modelValue` 从 `string` 放宽到 `string | null | undefined`，内部默认 `''`。
★ 这类「组件比调用点严格」的错，`vue-tsc` 只在真接到调用处才报，
提前写组件时看不出来。
