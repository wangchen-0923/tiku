# 知否 · WorkBuddy 云托管部署方案

> ## ⚠ 本方案归档，不再实施
>
> 当前项目的实际部署走 **`deploy/server/`（自有服务器 + Docker Compose + 宿主机 Nginx）**，settings 为 `zhifou.settings.serverprod`。
> 本文件仅作 **WorkBuddy 云托管沙箱**的**备用路径**（自有服务器不可用时的应急备案），请勿据此实施；两轨不能混用（沙箱轨需摘除 `django.contrib.postgres`，自有服务器轨必须保留）。
>
> 版本 v1.0 ｜ 架构：高见远 ｜ 范围：只做设计与改动清单，**不改业务代码**

## 1 结论摘要

**推荐方案**：单进程 Django（gunicorn `1 worker × 4 thread`）同时提供 `/api/v1/` + SPA + `/admin/`；数据库用**沙箱内 SQLite（WAL）**，随包带「种子库」，启动时若库不存在即复制；媒体文件外置 **S3 兼容对象存储**；Redis / Celery 全部降级关闭（`locmem` + `thread` + 任务 inline）。

**不可回避的三条代价**：
1. **数据持久性存疑**：沙箱磁盘在**重新发布/重建实例**时可能被替换 → 老师新录的题、学生作答可能回滚。测试期必须提供「导出备份」动作，正式使用再切方案 A。
2. **单实例**：登录限流、AI 令牌桶、AI 幂等锁只在**进程内**有效；横向扩容即失效（`base.py:284-293` 已写明该风险）。
3. **无 OCR / 无队列**：扫描件导入需完整依赖档；扫码识别与学情重算改在本进程内跑，长任务会占线程。

若业务要求「重启不丢数据」，必须走 §7 方案 A（外部托管 PostgreSQL），其前置条件是平台**放开 psycopg 驱动**（待确认）。

## 3 平台约束 → 设计推论

| 约束 | 推论 |
|---|---|
| 单端口、监听 `PORT`、绑 `0.0.0.0` | 不引入 Nginx；静态与 SPA 由 Django 进程承担；gunicorn `--bind 0.0.0.0:$PORT` |
| 无 PG/Redis/MQ | 必须可无 broker 启动：`CELERY_BROKER_URL=memory://`、`ZF_CACHE=locmem`、`ZF_TASK_MODE=inline`、`ZF_SCAN_RECOGNITION=thread` |
| 预检拒 psycopg/pg/ioredis 驱动 | 依赖清单一律不含 `psycopg`/`psycopg2`/`pgvector`/`redis`；连 `django.contrib.postgres` 也要摘掉（见 §2） |
| 上传排除 node_modules/.git/构建产物 | `web/dist` 需在本地构建后**复制**进包内（如 `server/spa/`），不能靠平台构建 |
| TLS 由反代终止并带 `X-Forwarded-Proto` | 保留 `SECURE_PROXY_SSL_HEADER`（`production.py:25`）；`/health/` 加入 `SECURE_REDIRECT_EXEMPT`，避免探针被 301 |
| 公网域名 `*.workbuddy.link` | 二维码无需重新构建：`studentBaseUrl()` 未配 `VITE_STUDENT_BASE_URL` 时回落 `location.origin`（`web/src/api/assignment.ts:388-395`） |

## 4 部署架构

```
Browser ──HTTPS──▶ 平台反代(TLS) ──HTTP──▶ gunicorn(1×4) :$PORT
                                              ├─ WhiteNoise  /static/*(admin)  /assets/*(SPA)
                                              ├─ Django 路由 /health/ /admin/ /api/v1/
                                              ├─ SPA 兜底  其余 GET → spa/index.html
                                              ├─ SQLite    server/db.sqlite3 (WAL)
                                              └─ S3 兼容   media 字节
```

**SPA history 兜底优先级**（`createWebHistory()`，`web/src/router/index.ts:19`；现状 `urls.py:47-56` 无兜底）：

| 顺序 | 前缀 | 处理 | 说明 |
|---|---|---|---|
| 1 | `/static/`、`/assets/` | WhiteNoise | 不走 Django 路由，命中即返回文件 |
| 2 | `/health/` | `health` 视图 | 探针，免认证 |
| 3 | `/admin/` | admin | 静态已 collectstatic |
| 4 | `/api/v1/` | include | 未知子路径仍是 404，**不会**被 SPA 兜底成 200 的 HTML 页 |
| 5 | `/status/` | `homepage` 状态台 | 原 `/` 迁到此（SPA 要占 `/`） |
| 6 | 其余（`/`、`/login`、`/assignments/12`、`/s/<token>`） | `spa_index` | 仅 GET/HEAD；**前缀黑名单**内 404 |

兜底视图必须自己做黑名单（`api/`、`admin/`、`static/`、`media/`、`health/`、`status/`），不靠正则顺序——顺序会被后来新增的 `include()` 破坏。落地写法（`zhifou/spa.py` + `urls.py` 末尾两行）：

```python
# spa.py
_RESERVED = ("api/", "admin/", "static/", "assets/", "media/",
             "health/", "status/", "favicon.ico")

def spa_index(request, path=""):
    if request.method not in ("GET", "HEAD") or path.startswith(_RESERVED):
        raise Http404                      # /api/v1/typo 仍 404，不被兜底成 200
    html = (Path(settings.ZF_SPA_DIR) / "index.html").read_text("utf-8")
    return HttpResponse(html, content_type="text/html; charset=utf-8",
                        headers={"Cache-Control": "no-cache"})

# urls.py（原有 urlpatterns 之后）
path("status/", homepage),                      # 状态台从 / 迁走
re_path(r"^(?P<path>.*)$", spa_index),          # 必须最后
```

`/api/v1/` 命中顺序天然优先（Django 按 `urlpatterns` 顺序匹配，`include()` 在前）；`/admin/`、`/health/` 同理。`/static/`、`/assets/` 由 WhiteNoise **中间件**在路由之前拦掉，缺失文件回落 Django 后命中黑名单 → 404（不会返回 HTML 造成白屏）。

**进程选型**：gunicorn（WSGI 已有 `zhifou/wsgi.py`，不需要 uvicorn/ASGI）；`--workers 1 --threads 4 --worker-class gthread --timeout 120 --graceful-timeout 30`。**worker 必须为 1**：SQLite 写锁 + 进程内缓存 + OMR 单线程池（`apps/omr/runner.py:31-33`）都假设单进程。`start.sh` 先 `cd server` 再执行，保证 `BASE_DIR` 相对路径与本地一致。`/` 会由 WhiteNoise 直接命中 `spa/index.html`（60s 缓存，发版后最多旧 1 分钟），其余前端路由走 `spa_index`。

## 7 数据方案

| 维度 | A 外部托管 PG（Supabase/Neon） | B 沙箱 SQLite（推荐） |
|---|---|---|
| 预检 | **被拒**：必须装 psycopg，命中驱动黑名单；规避只能运行期 `pip install`（依赖出网、不确定合规） | 合规：依赖清单无驱动 |
| 持久性 | 强（重启不丢） | 弱（重启回滚种子） |
| 并发 | 多 worker 安全 | 单 worker + WAL 可用；写并发 >1 会 `database is locked` |
| 迁移成本 | 低：`pg_dump`/`pg_restore` 即可，**无需 pgvector**（84 个迁移文件无 `CREATE EXTENSION`） | 中（PG→SQLite 类型转换 + 重建种子） |
| 向量检索 | 可用（未来接 pgvector 只要加扩展） | 不可用（二期才需要，`embedding` 当前只是 JSONField） |
| 结论 | 若平台放开 psycopg（或允许运行期安装），**改这一项即可**，代码零改动，只需保留 `django.contrib.postgres` | **本期采用**（唯一合规解） |

**迁移步骤（PG → SQLite 种子库）**
1. 本地：`python deploy/cloud/build_seed.py --out seed/zhifou.sqlite3`（Django ORM 逐表复制，保留原主键）。
2. 迁移顺序按 `LOCAL_APPS` 反拓扑序（`base.py:51-69`）：`org → accounts → knowledge → questionbank → paper → assignment → response`，FK 已由顺序满足；用 `transaction.atomic` 整包提交，失败可重来。
3. 校验：题目 1946 / 选项 5642 / 试卷 30 / 作答 240 / 资源 513，逐表比对。

**已知坑**
- **自增主键**：SQLite 显式插入更大 rowid 会自动抬高 `sqlite_sequence`，无需 PG 的 `setval`；但 `AutoField` 表若导入顺序错乱仍需复查。
- **类型**：`BigIntegerField`（`simhash` 63bit，`dedup.py:28-33` 注释已考虑）、`DecimalField`、带时区 `DateTime` 均可用；**不要**把 PG 的 `timestamptz` 写成本地时间。
- **PII 密文**：若 `pii_mapping` 有数据，云端必须用同一 `ZF_PII_KEK`，否则解密失败（本库 0 行）。
- **媒体**：活跃 369 条里有 106 条无文件（80 配图 + 26 答题卡 PDF）→ 迁移脚本必须先输出缺失清单，别把「云端图裂」误判成部署故障。
- **不要上传** `server/db.sqlite3.dev-only`（13MB，且只有 1944 题、0 试卷，是过期自检库）与 `__pycache__`。

## 10 风险清单

**会阻塞上线**
1. **`django.contrib.postgres` 强制 psycopg**：不摘除则 SQLite 也起不来 → 已在 `cloud.py` 覆盖 `INSTALLED_APPS`，发布前 `manage.py check` 必须过。
2. **依赖安装超时**：`opencv-python-headless`+`rapidocr-onnxruntime`+`onnxruntime` 约 200MB，且 onnxruntime 仅提供 glibc/manylinux wheel → 沙箱若为 Alpine 必然失败。规避：先发**精简档**（去 rapidocr）验证链路，再决定是否加 OCR。
3. **启动未绑定 `PORT`/未绑 `0.0.0.0`**：平台探活失败 → `start.sh` 显式 `--bind 0.0.0.0:${PORT}`。
4. **`SECURE_SSL_REDIRECT` 打回探针**：`/health/` 被 301 → 加 `SECURE_REDIRECT_EXEMPT`。

**影响功能**
5. **重启丢写**：新录入、学生作答归零 → 上线前明确告知；必要时切方案 A。
6. **媒体 167 条缺失 + 沙箱磁盘**：不配 S3 时重启后图片全丢 → 强制 `ZF_STORAGE_BACKEND=s3`，且发布前跑一致性比对；**无论哪条轨道，都不要在 Web 服务器上开放 `/media/` 静态别名**（全仓零引用该 URL，开放后即等于给含学生信息的扫描件开匿名下载口）。
7. **无 OCR 档**：扫描件/拍照导入报 `OCR_UNAVAILABLE`（`ingest/extract.py:143-153`），电子版 PDF/DOCX/XLSX 导入不受影响。
8. **SQLite 写锁**：全班同时提交会出现 `database is locked` → `PRAGMA journal_mode=WAL`、`busy_timeout=5000`，并把 gunicorn 线程压到 4。
9. **AI Key 出网**：沙箱若限制外网，AI 接口超时 → 先探一次 `urllib` 到 `api.deepseek.com`。

**体验问题**
10. **`/admin` 无样式**：漏 `collectstatic` → `start.sh` 每次启动都跑。
11. **CSRF**：同源 HTTPS 下 admin 登录正常；若平台用不同域回源，需 `CSRF_TRUSTED_ORIGINS`。
12. **时区**：库内全 UTC、展示按机构时区，跨时区用户会看到「差 8 小时的作业截止」→ 验收时专门核一次。
13. **Argon2 缺失**：`PASSWORD_HASHERS` 首选 Argon2（`base.py:159-162`），未装 `argon2-cffi` 会回退 PBKDF2（不报错但更慢）→ 依赖清单必须含它。
14. **二维码域名**：本地构建不会写死域名，但若曾设 `VITE_STUDENT_BASE_URL` 会编进产物 → 构建前确认 `web/.env.local` 不存在。
15. **`X-Forwarded-For` 未透传**：`_client_ip()` 只信该头（`accounts/views.py:44-63`），不透传则全体按代理 IP 共用一个限流桶 → 发布后实测一次登录失败计数。
16. **PDF 字体观感**：已确认有 `STSong-Light` CID 兜底（`textutil.py:121-180`、`sheet/render.py:25`），缺系统字体不会满页方框；但 Linux 上无 Noto 时会退成宋体，版式需肉眼复核一次答题卡。
