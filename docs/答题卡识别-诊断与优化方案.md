## 一、真实数据诊断

### 1.1 人工介入率：56%

| 卡状态 | 张数 | 平均置信度 | 含义 |
|---|---|---|---|
| AUTO_OK | 19 | 1.000 | 机器直接通过 |
| REVIEWED | 23 | 0.692 | 已人工仲裁 |
| NEEDS_REVIEW | 5 | 0.640 | 等待人工 |
| VOID | 4 | 0.150 | 判废 |

**51 张有效卡里有 28 张需要人工处理（55%）。** 这个比例决定老师愿不愿意用——识别率不是"能不能识别"，而是"要不要重看一遍"。

batch 20 更典型：22 张卡，21 张待仲裁。

### 1.2 填涂比例分布（941 个最强点 / 2109 个非最强点）

| 指标 | 最强项（学生涂的） | 非最强项（没涂的） |
|---|---|---|
| 最小 | 0.005 | — |
| 平均 | — | 0.073 |
| p99 | — | **0.236** |
| 最大 | — | **0.875** |
| ≥0.15 | — | 140 个（6.6%） |
| ≥0.12 | — | 334 个（15.8%） |

### 1.3 三个结论

**结论 1：`empty=0.15` 正好切在噪声带中间。**

非最强项的 p99 是 0.236，而 0.12–0.16 这一带全是浅痕、铅笔屑、扫描噪点（334 个点在 0.12 以上）。这些点一旦 ≥0.15 就判 `UNCERTAIN`，而 `validators.py:213` 的规则 10 是**一票否决**：

```python
if out.uncertain_items:
    out.card_status = ST_NEEDS_REVIEW
```

即：**一张 25 题的卡，只要有 1 个空涂点沾到 0.15，整张卡 25 题全部进人工复核。**

实证（card 34，seq 1）：D=1.0（真涂），B=0.1587（噪点）。就因为超出阈值 0.0087，整卡置信度被拉到 0.408，产生 3 项仲裁。

**结论 2：0.875 不是噪声，是真双涂，而绝对值判别分不开这两类。**

噪声上沿约 0.16，真实多填在 0.45–0.875。中间 0.16–0.45 这一段用绝对阈值怎么切都是错的：切低了多填漏检，切高了噪声误报。必须引入**相对判据**（次高/最高 的比值），而当前算法完全没有这个维度——`thresholds.py:98 classify()` 只看单个 fill_ratio。

**结论 3：噪声水平在同一张卡内部也不均匀。**

行首/行末、有涂改区、扫描仪边缘的噪声明显更高。用整页一个固定 empty 阈值，等于按最脏的区域定标准，干净区域被误伤。

## 二、五项需求逐条

### 需求 1 · 漏填/多填/不规范不该混进"答错"

**先把真实链路说清**（我逐层查证）：

1. `pipeline.py:276` `_answers_from_items` 对每题输出 `labels = list(it.filled)`
2. 单选 0 涂 → `validators.py:119` 规则 1 记 `NO_MARK_Qn` 并进 `uncertain_items`
3. 浅涂（0.15–0.45）→ 规则 10 记 `UNCERTAIN_Qn`，同时 `resolved_answers[seq] = filled`（可能是空列表）
4. `scan_service.py:499` `if not seq or not labels: continue` → **空答案不写 Response**
5. 批改时找不到 Response → 按"未作答"处理 → **0 分**

所以问题不是"被标成错"，而是 **"识别不出来"和"真的没答"在最终成绩里长得一模一样**。老师看不出哪道要重看，学生看到的也只是一个 0 分。

**建议：三档分离，不要二值化。**

| 情形 | 现状 | 建议 |
|---|---|---|
| 正常涂点 | 判对/判错 | 不变 |
| 漏填 / 浅涂 / 多涂 / 采样越界 | 整卡进仲裁（拖累全班） | 单题标 `NEEDS_REVIEW`，只这一题进待确认，**不阻塞整卡** |
| 老师已确认 | 按确认值 | 不变 |

技术上：`ScoreState` 已有 `NEEDS_REVIEW`（`common/constants.py:194`），不用加枚举。关键是**规则 10 从"整卡否决"改为"单题标记"**，让一张卡上 24 题正常、1 题存疑时，那 24 题照常出分。

> ⚠️ 这条会改变现有"宁可进仲裁也不错判"的立场（`validators.py:6` 明确写了这个原则）。
> 我同意改，但必须同时保证：存疑题在成绩单上**明确可见**，否则等于把风险从"多仲裁"换成"静默错分"。
> **需要你拍板：存疑题算 0 分、不计入总分、还是按识别到的最高项暂定？**

### 需求 2 · 正确绿 / 错误红 / 错题同时显示正确答案位置

**现状**（比想象中更接近了）：

- `display.py:7-8` 注释已写明：*"标注图只画学生选中的选项：绿色 = 选中且正确；红色 = 选中且错误；未作答不标"*
- `display.py:175` `if label not in selected: continue` ← **正确答案的位置完全不画**

所以绿色已经有了，缺的正是你要的后半句：**错题要同时把正确答案该在的位置标出来**。

**改动点：**

1. `annotate_page()` 签名缺正确答案。当前只有 `responses_by_sheet_seq` + `scores_by_item_id`，需要把正确答案传进来（或在 `scores` 上带 `correct_answer`）。
2. 当 `score.is_correct is False` 时，对正确答案的涂点画**绿色空心框**（`cv2.rectangle` 线宽 2，不填充）。**不能填充**——填了会盖住学生原来的笔迹，老师就看不出学生到底涂了什么。
3. 图例文案要改：现在是"绿=正确 红=错误"，改为"绿=答对 / 红=答错 / 绿框=正确答案位置"。
4. 表格层（`GradingWorkbenchView.vue:1075-1086`）：学生答案与正确答案两列目前都是纯文本无色。学生答案错→红，正确答案→常绿。

颜色沿用现有 `COLOR_CORRECT=(60,180,75)` / `COLOR_WRONG=(40,40,220)`，不新增色值。

### 需求 3 · 提高识别准确率与速度

**准确率（按性价比排序，都要用你的真实卡回放验证）：**

| 优先级 | 改动 | 预期 |

| P2 | `BUBBLE_SAMPLE_RATIO` 0.58 → 0.50 | 更靠中心，少采到框线和印刷字母；需 A/B 对比 |
| P3 | `_fill_threshold` 的 `bg-40 clamp[110,190]` 加 Otsu 兜底 | 浅铅笔（灰度 190+）场景 |

**速度（先 profile，别盲改）：**

### 需求 4 · 学号框与选项框大小一致 + 增加填空行距

**尺寸不一致的根因（两处不一致叠加）：**

| 位置 | 代码 | 公式 |
|---|---|---|
| 选项（v3） | `layout.py:703` | `min(4.6, col_w * 0.72)` |
| 选项（v4） | `layout.py:704` 同源 | 未乘 `box_scale` |
| 学号（v4） | `layout_v4.py:577` | `min(4.6 * box_scale, col_w_try * 0.72)` ← **乘了 box_scale** |
| 学号（v3） | `layout.py:700` | `min(4.6, col_w * 0.72)` |

两重偏差：① 学号乘了 `box_scale` 选项没乘；② 学号的 `col_w = sn_w / per_row` 通常小于选项列宽 → 学号框实测更小。

**修法**：抽出共用函数 `bubble_size(col_w, box_scale)`，选项与学号都调用，并加断言（两者差 < 0.1mm）。

**填空行距**：`layout.py:1090`

```python
line_h = round(font_mm * 1.9 + 1.6, 2)   # 10.5pt → 8.63mm
```

建议 2.2–2.4 倍（≈9.7–10.4mm），或做成 `style.fill_line_gap_mm` 让老师可调。

> ⚠️ **这两条都改变模板几何**，必须升 `template_version`：旧卡的采样点、切图矩形按旧版式算，改尺寸后旧卡会全部错位。
> **需要你拍板：现有模板是否可作废重建？** 若不能，只能新模板生效、旧模板保持原样（要增加版本分支逻辑，工作量翻倍）。

### 需求 5 · 填空题有多个小题时，切题该怎么处理

**先分清两种"多小题"，它们的处理完全不同：**

**A 型：每个小题是独立题号**（全卷连续 seq，`sheet/sections.py:20` 的设计）
→ 现状**已经正确**：每个小题独立 `item` → 独立 `fill_blanks` entry → 独立切图。不需要改。

**B 型：一个大题下 (1)(2)(3) 共用一个 seq**（`blanks=3, per_line=1`）
→ 现状 `crops.py:118 _rect_of_fill_blank()` 把该题**所有行**合成一个外接矩形，一张切图含三个空，一次评分覆盖三空。

**B 型的三个选项：**

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| ① 整题一图（现状） | 一题一图 | 上下文完整 | 无法逐空给分——而 `sections.py:203-220` 已有 `blank_scores` 每空分值，数据层支持却用不上 |
| ② 按空切 | 一个空一张 | 可精确到空 | 45 人 × 3 空 = 135 张图，阅卷负担爆炸；切碎后看不到上下文 |
| ③ **按行切 + 复用 part_index** | 每行一个 part | 兼顾上下文与粒度 | 改动集中在 `blocks_for_page` |

**推荐 ③**，理由是现成机制已经在：

`SubjectiveCrop` 本来就有 `part_index` / `part_count`，`omr/models.py:310` 的注释写明它的用途——*"同一题多段时的段号（跨页作文）。一次评分覆盖整题，所以前端要能把 1..n 段按顺序摆在一起看"*。

**多小题和跨页作文是同构的**：都是"一题的多块作答区，按顺序拼起来看"。复用这个机制，不用新造概念。

具体改动：
- `crops.py:201-208` 填空题分支：从产出 1 个 part 改为按 `lines` 展开，`part_index` = 行号
- 把 `_rect_of_fill_blank` 拆出单行的 `_rect_of_fill_line(line)`
- 前端 `AssignmentReviewView.vue` 已支持竖向拼接，不用改

**前提**：需求 4 把行距加大后，行间空白才够，按行切才不会把上一行的字切进来。所以 **P4 必须先于 P5**。

**如果将来要逐空给分**（不只是逐行）：part 就是天然载体——一行内有多个空时，可再按 `blank_index` 细分 part。但这会让图变碎，建议先做按行，看老师反馈再决定。

## 三、实测修正（2026-10-21，回放脚本跑过之后）

用 `scripts/omr_threshold_replay.py --batch 20 --sweep` 对 22 张真实卡（660 题）回放，

  "$PY" scripts/omr_threshold_replay.py --batch 20 --sweep

### 3.1 阈值不是瓶颈：调整 empty 零收益

| empty | 浅涂 | 漏填 | 存疑合计 |
|---|---|---|---|
| 0.15 | 22 | 2 | **26** |
| 0.20 | 19 | 5 | **26** |
| 0.25 | 17 | 7 | **26** |
| 0.30 | 15 | 9 | **26** |

提高 empty 只是把「浅涂」换算成「漏填」，**存疑总数恒为 26**。
那 22 个浅涂点的填充率多数在 0.30–0.45 之间，远高于噪声上沿（p99 = 0.236），
它们是**真实的浅涂笔迹**，不是噪点。上一节「0.15 切在噪声带里」的判断对噪声成立，
但对这 22 个点不成立——它们是学生涂得淡，不是扫描脏。

### 3.2 相对判据无效，反而有害

| rel | 多涂题数 | 存疑合计 |
|---|---|---|
| 0（关闭） | 2 | 26 |
| 0.55 | 4 | 28 |
| 0.45 | 7 | 31 |

真实多涂已被绝对阈值（`次高 >= filled`）抓住，加相对判据只会把 0.20–0.45 的
浅痕误认成第二涂点。**结论：不加。**

### 3.3 真正的瓶颈：`0.6×min` 把单题浅涂放大成整卡否决

21 张待仲裁卡的 `fail_reason` 统计：

| 原因 | 张数 |
|---|---|
| 整卡置信度 0.57–0.82 低于阈值 0.90 | **18** |
| 学号不完整 / 未识别 | 3 |

而涂点存疑只波及 **7/22** 张卡。也就是说：**82% 的仲裁与涂点判定无关**，
是置信度聚合公式造成的。

`confidence.py:100`：

```python
return round(_clamp(W_MIN * min(item_confidences) + W_MEAN * mean(...)), 3)
#  W_MIN = 0.6, W_MEAN = 0.4
```

一道浅涂题（top≈0.55, second≈0.35）→ `margin=0.20` → `conf = 0.20/0.30 = 0.667`。
整卡 = `0.6×0.667 + 0.4×1.0 = 0.80` < 0.90 → **整卡进仲裁**。

一道题拖垮 25 道题。这跟 `validators.py:213` 的规则 10 是同一类问题的两个副本。

### 3.4 三个候选改法（需选一个）

| 方案 | 改动 | 预期 | 风险 |
|---|---|---|---|
| A | `W_MIN 0.6 → 0.3`，`W_MEAN 0.4 → 0.7` | 单题不再主导整卡 | 真有 1 道烂题时整卡可能漏放 |
| B | `card_confidence_threshold 0.90 → 0.80` | 直接放行现有 0.80–0.89 那批 | 门槛整体降低，最粗糙 |
| C | 整卡判定改为「存疑题占比」（如 >20% 才拦） | 语义最准：偶尔一题≠整张作废 | 需新增计算，改动最大 |

我倾向 **A + C 组合**：`W_MIN` 降权解决"一题拖垮"，占比规则解决"什么时候真的该拦"。
B 不建议——它同时放宽了所有情形。

> 这一节的教训值得记住：**阈值类改动必须先回放再动手**。
> 凭分布图直觉调的参数，实测收益可能为零，甚至反向。
