# 七大模块 · 功能范围、关联、优先级与实现方案

> 成稿：2026-10-21 · 依据：`server/apps/*` 代码 + PostgreSQL 实测 + 前端路由清点。
> 本文只做**方案**，代码未动。每节标注了真实文件位置，便于逐条核对。

## 〇、先修正一个前提

这 7 个模块**不是全部从零开始**。核对结果：

| 你的判断 | 实际 |
|---|---|
| 科目管理与知识点管理「尚未建设」 | 模型、树查询、知识点新建、前置关系都在；**缺「科目增删改」和「知识点改/删/移动」** |
| 知识点下知识库管理「尚未建设」 | 后端 **完整 CRUD + 归档 + 采纳 + AI 拆条**；缺的是前端在知识点维度下的管理界面 |
| 公式输入「尚未建设」 | ✅ 确实为零。全仓无 katex / mathjax / latex 任何痕迹 |
| 私有题库与公共题库「尚未建设」 | ✅ 确实为零。`Question` 只有 `org_id`，没有可见性概念；`QuestionGroup` 是材料题组，不是题库 |
| AI 全链路「尚未建设」 | 已接 4 处（AI 出题、解析生成、导入配图、知识库拆条）；但 **`ai_prompt_template` 表 0 行**，场景目录没建 |
| 教师个人中心「尚未建设」 | ✅ 前端零页面。后端只缺「资料修改」一个方法 |
| 首页工作台「尚未建设」 | 现有 `HomeView` 是 250 行「概览」，只展示题库规模/健康/题型分布，**没有教学动作视角** |

**所以真实工作量集中在 4 处**：科目/知识点写操作、题库可见性模型、公式链路、工作台与个人中心页面。知识库与 AI 是「补界面 + 补场景」。

## 一、功能范围（做什么 / 明确不做什么）

### M1 科目与知识点管理

**做什么**
- 科目（`knowledge.Course`）：新增、编辑（名称/编码/学段/层次/课时/教材）、停用、软删；平台模板科目（`org=NULL`）只读，机构可「复制到本机构」。
- 层级组织：科目 → 章节（Chapter）→ 任务（Task）→ 知识点（Node），四层都支持改名/排序/删除。
- 知识点：编辑（名称/权重/排序）、**移动到其他任务**（改层级）、删除（有题则阻断并列出引用）、前置关系增删（接口已存在）。
- 知识点列表已带 `question_count` / `entry_count`（`views.py:420-430`），直接用来做「缺口可见」。

**不做什么**：不做知识点合并的 UI（后端 `nodes/{id}/merge/` 已有，走运维）、不做多教材版本并行。

### M2 知识点维度知识库

**做什么**
- 知识点详情抽屉内新增「知识库」页签：条目列表（按 `ACTIVE`/`ARCHIVED`、按来源筛选）、新建、编辑、归档、批量采纳。
- 条目与知识点是多对多（`node_ids`），一个知识点下可有多条、一条可挂多个知识点 —— 后端已支持，前端要如实展示。
- 展示「该知识点还缺知识库」标记：接口 `nodes/lacking-kb/` 已存在。

**不做什么**：不做版本历史、不做向量检索界面（`embedding` 字段留而不用）、不做富文本公式（等 M3）。

### M3 数学公式输入与渲染

**做什么**
- 编辑器：题干 / 选项 / 答案 / 解析四处支持公式，工具栏（分式、根式、上下标、求和积分、希腊字母）+ 实时预览。
- 存储约定：正文里用 `$...$`（行内）与 `$$...$$`（独立行），**不新增数据库字段**，沿用 `stem_html` / `stem_text` / `answer` / `explanation_html`。
- 渲染点必须全覆盖：题库列表预览、组卷预览、试卷导出（PDF/Word）、学生答题 H5、批改工作台、主观题阅卷的「答案与解析」窗口。
- 输入侧兜底：纯文本 `stem_text` 保留 `$...$` 原样，供 AI 与检索使用；展示侧才转 SVG。

**不做什么**：不做化学式/单位排版（`\ce{}`）、不做公式图片上传（会绕过语义）。

### M4 私有题库与公共题库

**做什么**
- 新增 `QuestionBank`（题库）：`kind = PRIVATE | PUBLIC`、`owner_org`、`name`、`subject/course`、`status`。
- `Question` 增加 `bank_id`：历史 1946 题在迁移里回填到各机构「默认私有库」。
- 可见性：`PRIVATE` 仅本机构；`PUBLIC` 全机构**只读引用**（平台管理员可写）。
- 组卷/选题：默认只看「本机构私有 + 公共」，可切换只看其一；引用公共题**不复制**（试卷快照已冻结，不存在后续被改动风险）。
- 题库维度统计：题量、题型分布、知识点覆盖率、难度分布。

**不做什么**（一期）：不做跨机构「授权共享」、不做「复制到本机构」、不做题库级权限成员表。这三项等真实共享需求出现再做（对应 `03` 文档 P3-04）。

### M5 AI 全链路赋能

**做什么**
- 先把**场景目录**建起来：`AIScene` 常量 + `ai_prompt_template` 播种，把现有 4 个场景（AI 出题、解析生成、导入配图、知识库拆条）先入库，让「模板库」不再是空表。
- 新增 3 个高价值场景：
  1. **主观题评分建议**（批改页）：给参考答案 + 学生作答 + 评分点，输出 `suggested_score` 与理由，**只建议不落分**；
  2. **学情报告摘要**（分析页）：把已有统计数字转成教师可读的 3 段话 + 3 条教学建议；
  3. **组卷配比建议**（组卷页）：按目标总分与知识点覆盖缺口，建议题型/难度配比。
- 统一治理：脱敏（`masking` 已有）、计量（`ai/usage/` 已有）、留痕（`ai_call_log` 已有）、可回滚（建议与结果分表存）。

**不做什么**：不做自动批改直接给分、不做 AI 生成整份试卷一键发布（必须人工确认）。

### M6 教师个人中心

**做什么**
- 新路由 `/me`，五个页签：
  | 页签 | 内容 | 依赖 |
  |---|---|---|
  | 我的资料 | 姓名/手机/邮箱/头像 | 需新增 `PATCH /auth/me/` |
  | 安全设置 | 改密码（已有）、登录记录 | 需补 `audit` 端点 |
  | 我的资产 | 我创建的题目/试卷/作业 | 需列表加 `created_by=me` 过滤 |
  | AI 用量 | 本月调用量、按场景分布、最近日志 | `GET /ai/usage/`、`/ai/logs/` 已有 |
  | 偏好设置 | 默认班级、默认答题卡模板、首页默认视角 | 需 `PATCH /auth/me/preferences/` |

**不做什么**：不做多人协作/团队空间、不做消息中心（无消息模型）。

### M7 首页工作台

**做什么**
- 现有「概览」升级为工作台，三块：
  1. **待办**（可点击跳转，带数字）：待批改作业、待处理扫描卡、待发布草稿、待标难度题、待确认配图、零题知识点；
  2. **最近活动**：最近 5 个作业（状态 + 提交率）、最近 5 份试卷；
  3. **快捷入口**：新建题目 / 组卷 / 发布作业 / 扫描识别 / 学情分析。
- 数据由**一个聚合端点**返回（`GET /api/v1/dashboard/`），不让前端发 8 个并发请求。

**不做什么**：不做可拖拽自定义布局、不做学生端首页。

## 二、相互关联

```
            ┌──────────── M1 科目/知识点 ────────────┐
            │  (数据骨架：谁属于谁、层级与前置)        │
            └───────┬───────────────────┬────────────┘
                    │                   │
              ┌─────▼─────┐      ┌──────▼──────┐
              │ M2 知识库 │      │  M4 题库    │
              │(AI 的依据)│      │(题的归属)   │
              └─────┬─────┘      └──────┬──────┘
                    │                   │
                    └───────┬───────────┘
                     ┌──────▼──────┐
                     │  M5 AI 全链路 │  ← 输入质量 = M2/M4 的质量
                     └──────┬──────┘
                            │
   ┌────────────┐    ┌──────▼──────┐
   │ M3 公式     │───▶│ M6 个人中心 │
   │ (横切能力)  │    │ M7 工作台   │
   └────────────┘    └─────────────┘
```

三条关键依赖，决定顺序：

1. **M1 是骨架**：知识点不能改/删/迁移，M2 的宿主就是死的，M4 的分类维度也建不起来。
2. **M2 + M4 是 AI 的输入**：AI 出题靠 `kb_injection` 拿知识库条目、靠题库取同知识点样例。这两个不治理，M5 加再多场景也只是把差输入放大。
3. **M3 是横切能力**：它不影响谁先谁后，但**每多一道含公式的历史题，后面补公式的成本就多一分**；渲染点从题库一直贯穿到 PDF 导出，越晚接入点越多。
4. **M6 / M7 是末端消费者**：它们只读别人的统计，不阻塞任何模块，可以并行提前做，见效最快。

## 三、优先级

| 优先级 | 模块 | 理由 |
|---|---|---|
| **P0** | M1 科目/知识点管理 | 唯一「已有模型但改不了」的硬缺口；挡住 M2/M4 的组织维度 |
| **P0** | M2 知识库界面 | 后端已完整，投入产出比最高；AI 出题质量直接依赖它 |
| **P1** | M4 私有/公共题库 | 需要迁移 + 回填，风险最高，必须单独一批做；不做则「公共题库」无从谈起 |
| **P1** | M3 公式 | 横切且不能回退（学生已答过的题没法回头补），越早越好 |
| **P2** | M5 AI 全链路 | 依赖 M2/M4 的数据质量；先建场景目录，再逐个加场景 |
| **P2** | M7 首页工作台 | 需要新聚合端点，但改造面集中在一个页面 |
| **P3** | M6 个人中心 | 纯增量页面，不阻塞任何人 |

> 顺序建议：**M1 → M2 → M4 → M3 → M5 → M7 → M6**。
> 如果想让老师尽快看到变化，可以把 **M7 + M6 抽出来并行提前**（≈3.5 人日），不影响主线。

## 四、实现方案（逐模块）

### M1 科目与知识点管理

**后端补写操作**（当前缺口，逐条给位置）

| 端点 | 现状 | 要补 |
|---|---|---|
| `PATCH/DELETE /knowledge/courses/{id}/` | 只有 `GET`（`views.py:99`） | 改名/改编码/停用/软删；**有试卷或题引用时 409**，`data.blocking` 列出引用数 |
| `PATCH/DELETE /knowledge/nodes/{id}/` | 只有 `GET`（`views.py:453`） | 改名/权重/排序；`task_id` 变更即「移动层级」，需重算 `code`；**有题或知识库条目时 409** |
| `PATCH/DELETE /knowledge/chapters/{id}/`、`tasks/{id}/` | 只有 `GET/POST` | 同上；删除时子级必须为空，否则 409 并列出子节点 |
| `POST /knowledge/courses/{id}/clone/` | 无 | 平台模板科目复制到本机构（深拷贝章节/任务/知识点，不含题） |

**权限**：写操作一律 `IsOrgAdmin`（与现有 `NodeListCreateView.post` 一致，`views.py:478`）。

**删除策略**：全部**软删**（`SoftDeleteModel` 已有 `deleted_at`）；被引用时**绝不级联删题** —— 那会静默破坏历史试卷与学情。

**前端**：`KnowledgeView.vue`（现 879 行）左侧树加节点右键菜单（编辑 / 移动 / 删除 / 查看缺口），顶部加「科目管理」抽屉（列表 + 新建 + 编辑 + 停用）。

**风险**：知识点 `code` 是层级编码（如 `JXJC-C01-T02-K03`），改父级必须重算编码 —— 而编码被 `QuestionKnowledge` 之外的报表引用。建议：**编码只在创建时生成，移动时保留原编码**，避免大面积改写。

### M2 知识点维度知识库

**后端**：0 改动。`entries/` 已支持 `?node_id=&status=`，`entries/{id}/` 支持 GET/PATCH/DELETE，`entries/{id}/archive/`、`entries/adopt/`、`import/*` 均在。

**要修的两个既有缺陷**（勘查时发现，均已写在代码注释里）：
1. `EntryCreateSerializer` 未声明 `source_ref` → 传了被静默丢弃（`views.py:600` 注释记录）；
2. `EntryCreateSerializer` 把 `title` 设为必填，而服务层允许为空 → 接口比服务严，AI 拆条必须自己造标题。

**前端**：知识点详情抽屉新增「知识库」页签，含条目表格（标题/类型/来源/状态/更新时间）、编辑弹窗、归档、批量采纳；顶部显示「缺知识库」告警（`nodes/lacking-kb/`）。

### M3 公式输入与渲染

**存储**：不新增字段。约定 `$...$` / `$$...$$`，`stem_html` 与 `stem_text` 同时保留（后者是 AI 与检索的输入）。

**前端**：
- 依赖 `katex`（约 300KB，可只引 core + 常用宏）。
- 新增两个组件：`MathRenderer.vue`（把文本里的 `$...$` 转 DOM）、`MathEditor.vue`（工具栏 + 预览）。
- 接入点 6 处：题库列表、试卷预览、答题 H5、批改工作台、主观题阅卷、导出页。

**后端**：
- 新增 `POST /questions/check-formula/`（LaTeX 语法校验，返回错误位置），避免坏公式入库；
- `stem_text` 生成时保留公式原文（现有 `html_to_text` 会剥标签，`$...$` 不是标签，天然保留）。

**★ PDF 导出是最大风险点**：现有导出走 reportlab，**不认 KaTeX**。两条路：

| 方案 | 做法 | 成本 | 代价 |
|---|---|---|---|
| A（推荐） | KaTeX 渲染 → SVG → 转 PNG（300dpi）→ 插入 PDF | 中 | 清晰度受 DPI 限制，公式内文字不可选中 |
| B | 服务端 Node + KaTeX 生成 HTML → 换用 WeasyPrint/Chromium 打印 | 高 | 要引入 Node 运行时，部署复杂度上升 |

**建议先 A，导出质量达标后再评估 B。**

### M4 私有题库与公共题库

**数据模型**

```python
class QuestionBank(SoftDeleteModel):
    org      = FK(Org, null=True)        # 公共库为空（平台所有）
    owner_org= FK(Org, null=True)
    kind     = CharField(choices=[("PRIVATE","机构私有"),("PUBLIC","平台公共")])
    name     = CharField(200)
    course   = FK(Course, null=True)     # 可选：按科目建库
    status   = CharField(choices=[("ACTIVE","启用"),("ARCHIVED","归档")])
    created_by = FK(User)

# Question 增加
bank = FK(QuestionBank, null=True, on_delete=PROTECT)
```

**迁移三步**（必须按序，且先在 PG 上跑）：
1. 建表 + 加 `bank_id`（可空）；
2. 数据迁移：每个机构建「默认私有库」，把该机构全部题回填 `bank_id`；平台题库建「公共库」，把需要共享的题迁过去（**首期公共库可为空**）；
3. 把 `bank_id` 收紧为 `null=False`（确认无遗漏后再做）。

**可见性落点只有一个**：`QuestionQuerySet.for_org()`。所有列表/组卷/统计都走它，改这一处即可全链路生效 —— 不要在每个接口里各写一遍 `filter(bank__kind=...)`，那必然漏。

**组卷引用规则**：引用公共题 = 只读引用，不复制；试卷快照已冻结，公共题后续改版不影响历史卷。

**风险**：`bank_id` 回填失败会让组卷抽不到题（最坏情况：全空）。**必须先备份**：
```bash
docker exec -i tiku_postgres_15433 pg_dump -U zhifou -d zhifou --no-owner --no-acl | gzip > backup-pre-bank.sql.gz
```

### M5 AI 全链路

**第一步（不做新场景，先把地基修好）**
- 新增 `apps/ai/scenes.py`：`AIScene` 常量（`QUESTION_GENERATE` / `EXPLAIN_GENERATE` / `INGEST_FIGURE` / `KB_SPLIT` / + 新增 3 个）；
- `ai_prompt_template` 播种 4 条现有场景（当前表 **0 行**，模板库形同虚设）；
- 统一入口：所有 AI 调用必须经 `AIOrchestrator` + `sanitize` + `AITask` 计量（现有 4 处已符合，新增场景照抄）。

**第二步（3 个场景，按价值排序）**

| 场景 | 落点 | 输入 | 输出 | 人工确认 |
|---|---|---|---|---|
| 主观题评分建议 | 批改工作台右栏 | 题干+参考答案+评分点+学生作答 | `suggested_score` + 逐点理由 | 老师点「采纳」才落分 |
| 学情报告摘要 | 学情分析页顶部 | 现有统计 JSON | 3 段话 + 3 条建议 | 只展示，可复制 |
| 组卷配比建议 | 组卷页 | 目标总分+知识点覆盖缺口 | 题型/难度配比建议 | 老师确认后写入规则 |

**硬约束**：AI 输出**永不留痕为成绩**，只写 `*_suggestion` 字段/临时表；`ai_call_log` 必须能按场景+教师追溯。

### M6 教师个人中心

**后端三个小改动**
1. `PATCH /auth/me/`：可改 `real_name` / `phone` / `email`（`MeView` 现只有 GET，`accounts/views.py:99`）；
2. 列表过滤 `created_by=me`：`questions` / `papers` / `assignments` 三个列表加参数（当前只有创建时写 `created_by_id`，读时无过滤）；
3. `audit` 补 1 个端点 `GET /audit/logs/?actor=me`（该 `urlpatterns` 目前为空，是已知债）。

**前端**：`/me` 路由 + 5 个页签（见 §1）。头像上传若要做，依赖 `media` 端点（现仅 1 个），建议**首期用姓名首字母头像**，不引入上传链路。

### M7 首页工作台

**后端**：新增 `GET /api/v1/dashboard/`，一次返回：
```
{ todos: { pending_grading, pending_scan, draft_assignments, unmarked_questions,
           unconfirmed_figures, nodes_without_questions },
  recent: { assignments: [...5], papers: [...5] },
  quick: { classes, courses } }
```
