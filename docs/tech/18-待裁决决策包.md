## §1.0 先解释清楚：「锚点坐标」到底指什么（决策 1 的前置说明）

### 一句话

答题卡四角有**黑色方块**（锚点）。系统要把它**记在文件里**。问题是：**记方块上的哪个点？**

### 图示

```
        ┌──────────────────────┐
        │                      │
        │    ┌────────────┐    │
        │    │ ●← 中心     │    │  ← 记「中心」：坐标 = 方块正中
        │    │            │    │
        │    └────────────┘    │
        │    ↑                 │
        │    └─ 左上角          │  ← 记「左上角」：坐标 = 方块外框的左上角
        └──────────────────────┘

        两种记法相差 = 方块边长 ÷ 2 = 5.44 ÷ 2 = 2.72mm
```

### 为什么这 2.72mm 会出事

| 环节 | 按「中心」 | 按「左上角」 |
| --- | --- | --- |
| 生成答题卡的程序 | 写入 `(中心x, 中心y)` | 写入 `(左上x, 左上y)` |
| 扫描识别的程序 | 按中心找锚点 → **对得上** | 按左上角找 → **对得上** |
| 如果两边不一致 | 整体偏移 **2.72mm** | 整体偏移 **2.72mm** |

**偏移 2.72mm 的后果**（结合样例实测的框尺寸）：

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 选项框高 | 4.54mm | 样例实测 |
| **偏移量占框高** | **60%** | 采样点会落进**相邻的框**里 |
| 表现 | 每张卡都错、方向一致 | **看起来像"全班都答错了"，不像系统故障** |
| 回投影校验（A3） | 0.916% < 容差 1.0% | ⚠ **校验认为"合格"，不报错** ← 最危险 |
| 回投影校验（A4） | 1.295% > 容差 1.0% | ✕ 会被拦下，反而安全 |

### 选项

| 选项 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A（推荐）** | 统一记**方块几何中心**，并在文件里写一个显式字段 `"anchor_coord":"CENTER"` | ① 识别端做透视校正时**天然用中心点**，不需要任何加减运算 → **少一个出错点**<br>② 有显式字段，不靠约定 | 生成端画图时需 `坐标 − 边长/2`（封装一次即可） |
| B | 统一记**左上角**，字段写 `"TOP_LEFT"` | 生成端直观（矩形左上角就是坐标） | 识别端**必须记得 `+ 边长/2`**，漏一次就全错 |
| C | 不加字段，靠文档约定 | — | **不建议**：这正是要消除的歧义 |

**你的选择：`____`**（我仍建议 A，但如果你的团队觉得 B 更顺手也可以——**关键是必须有那个显式字段**）

## 决策 1 · ✅ 已确定：锚点坐标采用【中心点】

**你的确认**：锚点坐标采用中心点。

**已采纳**：`layout_json` 写入 `"anchor_coord": "CENTER"`，坐标为锚点方块的**几何中心**。

| 落地要点 | 说明 |
| --- | --- |
| 生成端（画答题卡） | 绘制时以 `(x - 边长/2, y - 边长/2)` 为左上角，但**写入文件的坐标是中心** |

| 单元测试 | 断言：模板锚点中心 → 校正后回投影偏差 < `anchor_max_deviation` |

**另需确认**：这个字段会在 `sheet_template.layout_json` 里落库，OMR 识别端读取时**若字段缺失应报错而非默认**（防止旧数据被误读）。

**答案：中心点 ✓**

## 决策 1b（新增，P0）· 尺寸体系：固定毫米 vs 纯比例？

### 问题由来

我先前把「题号列 6mm + 内部留白 3mm + 组间距 20.47mm」当作**固定毫米值**，结果在 A5 上算出**负的框宽**（物理上放不下）。

### 选项

| 选项 | 做法 | 后果 |
| --- | --- | --- |
| A | 每种纸张各自调一套毫米参数 | 维护 3 套参数；新增纸张要重新调参；**换纸容易错版** |
| **B（你的选择）** | **只定比例**：所有几何参数定义为「占可用宽的比例」，唯一基准是 A3 样例的一次量测 | **任何纸张自动缩放**；只量测一次；换纸不会错版 |

**你的确认**：不固定尺寸，只确定比例，这样不管用什么大小，布局都不会出问题。

**已采纳**，比例常量表（全部由 A3 样例反推）：

| 常量 | 值 | A3 上的绝对量 |
| --- | --- | --- |
| `MARGIN_RATIO` | 0.104377 | 31.0mm |
| `BOX_W_RATIO` | 0.033064 | 7.77mm |
| `BOX_ASPECT`（高/宽） | 0.5843 | 4.54 / 7.77 |
| `ROW_PITCH_RATIO` | 0.030340 | 7.13mm |
| `MARKER_RATIO` | 0.016553 | 3.89mm |
| `ANCHOR_RATIO` | 0.023149 | 5.44mm |
| `GAP_X_RATIO` | 0.087106 | 20.47mm |
| `OVERHEAD_RATIO` | 0.052415 | 12.32mm |

**自验证**：把比例代回 A3，算出 **7.77 × 4.54mm**，与样例逐像素量测**完全一致**。

**额外收益**：暴露出一条更本质的结论——**真正的约束不是纸张大小，而是「列数 × 选项数」**：

| 组合 | A3 | A4 | A5 |
| --- | --- | --- | --- |
| 4 列 × 4 选项（选择） | 7.77 ✓ | 5.49 ✓ | 3.87 ✓ |
| 6 列 × 2 选项（判断） | 4.90 ✓ | 3.46 ✓ | **2.44 ✕** |
| 6 列 × 4 选项 | 2.45 ✕ | 1.73 ✕ | 1.22 ✕ |

→ **判断题必须用 2 选项**（对/错）才放得下 6 列；**A5 上判断题需降到 5 列**。

**答案：纯比例体系 ✓**

## 决策 7（P0）· 题库难度全是 3.00，怎么解？

> **✅ 已裁决（2026-10-12）：A = 启发式初值 + 人工抽检。** 见上方结论表。

### 问题由来

实测（真 PostgreSQL）：

```
题库总量 1944，难度分布：{3.00: 1944}   ← 全部同一难度，无一例外
```

而个性化练习**按掌握度反推难度区间**：

```
学生全错 → mastery ≈ 0 → 目标难度 1.0
难度阶梯最多放宽 1.0 档 → 区间最多到 2.0
题库全是 3.00          → 永远落不进区间
```

结果是 `POST /practice/generate/` 返回：

```
HTTP 200  code=PRACTICE.BANK_INSUFFICIENT
message=题库不足：6 个题位无可用题目，本次不生成（不生成缺题的卷子）
```

### 影响

★ **「学生一生一卷的精准作业」是产品目标里的核心承诺，现在生成不出练习集。**
且**不报错**——界面显示「题库不足」，老师会以为题不够，
而实际是**难度字段没有分层**。

### 选项

| 选项 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A（建议）** | 补难度标注：借「题目编辑器」（`P1-26`）人工标注 + 启发式初筛后抽检 | **唯一真正解决**；难度是教学属性，本就该有标注 | 一次性数据工作；1944 题不可能全靠人工 |
| B | 难度阶梯放宽到 ±2.0（覆盖 3.00） | 一行改动 | **难度自适应形同虚设**：全班拿到同一难度的题 |
| C | 一期承认难度自适应不可用，练习只按**知识点**选题 | 不改代码不改数据 | 产品目标里的「精准」要打折；需在界面如实说明 |

### 我的建议

**A**，但分两步：先用启发式（题干长度 / 章节顺序 / 题型）给出初值，
再由教研在编辑器里抽检修正 —— 全人工不现实，全算法等于没标。

★ 注意：**选项 A 依赖 `P1-26 题目编辑器`**。
所以编辑器不只是 M2 里程碑的要求，也是**解这条的唯一通路**。
