# 20 · 难度快速打标页设计（P1-100b）

> **用途**：让教研/教师**快速给现有题目补难度标注**。
>
> 背景：题库 1945 题的 `difficulty_effective` 全是默认 3.00（`difficulty_manual` 只有 3 道有值），
> 而个性化练习按掌握度反推难度区间（全错 → 目标 1.0，阶梯最多放宽到 2.0）
> → **3.00 永远落不进区间** → `PRACTICE.BANK_INSUFFICIENT`，
> 「一生一卷的精准作业」**一道也生不出来**。
>
> 这是**数据缺口**，不是算法问题。本页面是**唯一的人工通路**。
>
> 上游依据：[10-学情与个性化练习规格.md](10-学情与个性化练习规格.md)（难度推导）、
> [18-待裁决决策包.md](18-待裁决决策包.md) 决策 7（**已裁决：A = 人工打标**）。

| 项 | 内容 |
| --- | --- |
| 文件版本 | v1.0 |
| 任务 ID | `P1-100b` |

## 一、为什么不做「启发式自动打初值」

原始设计是用「题干长度 / 章节顺序 / 题型 / 选项数 / 是否含计算」5 个信号合成初值。

**需求方否掉了，理由成立**：

> 这些信号**不一定真的反映难度**。题干长可能只是描述详细；
> 章节序靠后也可能只是编排习惯。

★ 难度是**教学判断**，不是能从文本表面特征推出的量。自动打初值会污染数据，
而污染后的难度比没有难度**更糟** —— 组卷会据此选出「看着像难题」的题。

★ 所以改成**人工打标**，并把效率做到最高（见 §三）。

---

## 二、页面形态

**独立路由**：`/questions/mark-difficulty`（从题库页工具栏入口进入）

```
┌──────────────────────────────────────────────────────────────────────┐
│  难度打标                    [课程 ▾] [仅未标注 ☑]     进度 12/1942  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  第 13 题                    JXJC-C01-T01-K01 金属材料性能分类        │
│  ──────────────────────────────────────────────────────────────────  │
│  题型：填空题     章节：第一章 金属材料与热处理 / 分析轴的力学性能    │
│                                                                      │
│  更换破损齿轮需要掌握齿轮的________与计算方法，以及根据已有参数        │
│  进行________等知识和技能。齿轮选配时应遵循________安全操作规程。     │
│                                                                      │
│  标准答案：参数 / 选配 / 7S                                          │
│                                                                      │
│  ──────────────────────────────────────────────────────────────────  │
│  难度：  [1 很易] [2 较易] [3 中等] [4 较难] [5 很难]                 │
│                                                                      │
│          [跳过]  [上一个]  [查看详情]                                 │
└──────────────────────────────────────────────────────────────────────┘
```

### 关键交互（需求方确认）

| 行为 | 说明 |
| --- | --- |
| **提交后自动跳下一道** | ★ 核心要求。标完即刻前进，不用点「下一题」 |
| 进度显示 | `已标 / 总数`，随时知道还剩多少 |
| 难度选择 | **1–5 五个按钮**（★ 只能整数 —— `difficulty_manual` 是 `IntegerField`） |
| 跳过 / 上一个 | 标不准的先跳过；选错了能回去改 |
| 查看详情 | 链接到题库详情抽屉（看配图、知识点、AI 证据） |
| 仅未标注 | 默认勾选 —— 避免重复标注已有的 |

### 键盘流（效率的关键）

| 键 | 行为 |
| --- | --- |
| `1`–`5` | 选难度并**立即提交 + 跳下一题** |
| `S` / `→` | 跳过 |
| `←` | 上一个 |
| `D` | 查看详情 |

★ **一键完成「选难度 + 提交 + 前进」**是效率的核心：
标 1900 道题如果每题要 3 次点击，是不可接受的。

## 三、效率估算

| 方式 | 每题操作 | 1942 题预计 |
| --- | --- | --- |
| 纯鼠标点选 | 点难度 → 点下一题（2 次点击） | 约 6–8 小时 |
| **键盘数字键** | 按 `1`–`5`（**1 次按键**） | **约 2–3 小时** |

★ 所以键盘流不是「锦上添花」，它是**这个页面能否被真正用起来**的决定因素。

---

## 四、写入口径

| 字段 | 写什么 |
| --- | --- |
| `difficulty_manual` | 人工选的 1–5（整数） |
| `difficulty_source` | 由服务层统一置为 **`MANUAL`**（★ 与「覆盖统计值」的 `MANUAL_OVERRIDE` 区分） |
| `difficulty_effective` | 由 `sync_difficulty_band()` 自动同步（人工优先级最高） |
| `difficulty_band` | 同上自动同步 |
| 审计 | 走 `audit_log.record_strict(action=A_QUESTION_STATUS…)`，记 before/after |

★ **必须复用 `QuestionEditService.update_question()`**，不另写写入逻辑 ——
否则会绕过 `sync_difficulty_band()`，出现「改了难度但档位没变」。

---

## 五、接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/questions/mark-queue/` | 取待打标队列（`?course_id=&only_unmarked=true&page_size=`） |
| `POST` | `/api/v1/questions/{id}/mark-difficulty/` | 打标（`{"difficulty": 3}`）→ 返回**下一题的 id** |

★ 第二个接口**直接返回下一题 id**，让前端不用再发一次「取下一题」请求 ——
键盘流下这是每道题都省的一次往返。

★ **队列顺序**：按 `id` 升序（稳定、可复现）。不用随机 ——
教研希望「标到哪了」是可续的，随机顺序没法续。

## 六、验收判据

| # | 判据 | 怎么验 |
| --- | --- | --- |
| 1 | 标一道题后 `difficulty_manual` 被写入 | 查库 |
| 2 | `difficulty_effective` 与 `difficulty_band` **跟着变** | 查库 / 看题库列表难度列 |
| 3 | `difficulty_source` = `MANUAL` | 查库 |
| 4 | **数字键 `1`–`5` 一键提交并前进** | 手工 |
| 5 | 进度计数正确（跳过不计入「已标」） | 手工 |
| 6 | 默认只列**未标注**的题 | 手工 |
| 7 | 队列顺序稳定可续 | 刷新后仍从同一位置继续 |

★ **第 2 条是重点**：它是「人工优先级最高」这条契约的落地证明。
`verify_questionbank_h5.py` 里已有同类断言（难度走 `difficulty_manual`），
本页只需保证**复用同一服务方法**。

## 七、与「启发式」的关系（保留说明）

启发式方案**未废弃**，只是**不作为本页的实现方式**。它更适合的场景是：

- 作为**教研的参考建议**（在页面上显示「系统建议：中等」，老师可采纳可否定）
- 或用于**批量粗筛**（先按建议分组，老师只复核离群值）

★ 若将来要做，应作为**独立增强项**，且必须**明确标记为「建议」而非「已标注」**，
不能让 AI 的猜测混进 `difficulty_manual`（那是人工标定的字段）。
