# 第一部分：配置项

## 一、配置体系

### 1.1 三层优先级

```
机构级（数据库 org.ai_config / org.grading_config）
  > 环境变量（ZF_* 全局默认）
    > 代码默认值（apps/common/constants.py 的 DEFAULTS）
```

### 1.2 访问方式（**唯一入口**）

```python
# apps/common/config.py
from typing import Any
from apps.common.constants import DEFAULTS

def get_config(key: str, *, org=None, channel: str | None = None, **overrides) -> Any:
    """
    按优先级取配置值。

    key 形如 "omr.fill_threshold_filled"、"grading.fill_blank.fuzzy_accept"
    channel 用于 OMR 这类分通道配置（UPLOAD / PHONE_H5）
    """
    if org is not None:
        section, _, field = key.rpartition(".")
        cfg = _org_section(org, section)                  # 从 ai_config/grading_config 取
        if cfg is not None:
            if channel and isinstance(cfg.get(field), dict):
                v = cfg[field].get(channel)
                if v is not None:
                    return v
            if field in cfg:
                return cfg[field]
    env_key = "ZF_" + key.replace(".", "_").upper()
    if env_key in os.environ:
        return _cast(os.environ[env_key], DEFAULTS[key])
    return DEFAULTS[key]
```

**禁止**：

```python
# ❌ 错误：机构级覆盖会失效
filled = 0.45

# ❌ 错误：绕过优先级
from django.conf import settings
filled = settings.OMR_FILLED

# ✅ 正确
filled = get_config("omr.fill_threshold_filled", org=org, channel=card.capture_channel)
```

## 五、OMR 识别

### 5.0 识别执行方式（部署级环境变量）

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `ZF_SCAN_RECOGNITION` | `thread` | `thread`：本机单线程后台识别，不依赖 Celery；`sync`：请求内同步，适合脚本/极小批量；`celery`：投递 `p0_critical` 队列 |

- `thread` 模式上传后立即返回 `THREAD`，批次状态由 `PROCESSING` 最终落 `COMPLETED` / `WAITING_REVIEW` / `FAILED`。
- `celery` 模式上传只返回 `QUEUED`，**不代表已识别**；必须另有 worker。生产切换：

```powershell
$env:ZF_SCAN_RECOGNITION="celery"
celery -A zhifou worker -Q p0_critical
```

- 线程/投递异常会把批次置 `FAILED`，失败原因写在 `quality_report.fail_reason`（不改表结构）。

## 十、AI 编排

### 10.0 ★ 厂商接入（2026-10-17 新增，**部署级，走环境变量**）

> ★★ 这一节补的是一个**真实的缺口**（`14-缺陷登记册` V-17）：在它之前，
> 全后端**没有任何厂商适配器**（唯一内置 `EchoProvider` 明确不联网），
> 而且**全项目没有一处调用 `register()`** → `registered() == []`
> → `routing.pick_route()` 因「未注册 provider」跳过全部候选并抛错。
> 即：**AI 层万事俱备，只差模型**，而文档把它写成了「等 API Key」。

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `ZF_AI_API_KEY` | **无默认** | API 密钥。★ **必须显式设置**；缺失时抛 `ProviderUnavailable`（「这是配置问题、重试无用」） |
| `ZF_AI_BASE_URL` | `https://api.deepseek.com/v1` | 接口地址（OpenAI 兼容） |
| `ZF_AI_MODEL` | `deepseek-chat` | 默认模型名 |
| `ZF_AI_ROUTES` | 空 | **部署级任务路由覆盖**（见下） |

**为什么密钥只走环境变量、不读 `org.ai_config`**：

- 机构管理员可改 `ai_config` → 密钥会随序列化、备份、审计接口流动；
- 环境变量在进程内只读、轮换不动库；
- ★ `org.ai_config["routing"]` 仍然**可以**配路由（provider/model/单价），**但那里不放密钥**。

**`ZF_AI_ROUTES` 格式**（值为候选数组，从强到弱）：

```json
{
  "generate_question": [
    {"provider": "openai_compat", "model": "deepseek-chat",
     "price_in_per_m": 1.0, "price_out_per_m": 2.0}
  ]
}
```

优先级：`extra`（本次调用显式传入）> **`ZF_AI_ROUTES`** > 机构配置 > 平台默认（`DEFAULT_ROUTES`，全是 `echo`）。

★ 三条刻意设计：

1. **单价必须给对**（缺省 0.0）—— 单价 0 会让「贵模型跳过、便宜模型兜底」的**预算降级失效**。
2. **非法配置不抛异常**：JSON 拼错 / 未知任务名 / 缺 `model` → **忽略整份覆盖** + error 日志 + 回落平台默认。`pick_route` 在编排主路径上，一个环境变量拼写错误不该把 AI 能力整体打挂。
3. **不修改 `DEFAULT_ROUTES`**：平台默认保持 `echo`（测试/开发零外部依赖），要真实调用必须**显式**设 `ZF_AI_ROUTES`。忘了设的后果是「还是 echo」，不是「悄悄调了真模型」。

**判定逻辑**（对应设计文档 7.7.5）：

```python
def gen_availability(org, subject, grade_band, node_id) -> GenAvailability:
    coverage = kb_coverage_for_node(org, subject, grade_band, node_id)
    bank_size = usable_question_count(org, subject, grade_band)
    if coverage < get_config("ai.gen_available.limited_kb_coverage_min", org=org):
        return GenAvailability(allowed=False, reason="KB_TOO_LOW",
                               message="知识库内容不足，AI 生题暂不可用")
    if coverage < get_config("ai.gen_available.kb_coverage_min", org=org):
        return GenAvailability(allowed=True, limited=True, reason="LIMITED",
                               message="仅部分知识点支持生题")
    if bank_size < get_config("ai.gen_available.bank_size_min", org=org):
        return GenAvailability(allowed=True, limited=True, reason="BANK_SMALL",
                               message="题库规模较小，建议优先补充题库")
    return GenAvailability(allowed=True, limited=False)
```

# 第二部分：提示词库

## 十六、模板规范（七段结构）

每个模板必须包含以下七段，缺一不可：

```
1. [角色]    学科与教龄设定
2. [任务]    要做什么
3. [约束]    硬性要求（JSON、公式格式、不得改动数字、只能引用给定编号）
4. [术语]    glossary 注入（学科术语规范）
5. [示例]    few-shot（2–3 个该科目真实样例）
6. [依据]    ★ 知识库检索内容，带 [K1][K2] 来源编号
7. [输入]    待处理数据
```

**模板管理纪律**：

| 纪律 | 说明 |
| --- | --- |
| 只增不改 | 变更必须**新建 version**，不得原地修改 |
| 必须关联 | `ai_call_log.prompt_version` 必须记录，否则无法追溯结果来源 |
| 必须评估 | 每次变更必须跑评估集（见 12 文档），输出对比报告后再决定启用 |
| 匹配优先级 | `机构+科目+学段 > 平台+科目+学段 > 平台+科目 > 平台通用` |
| 状态唯一 | 同一 `(org_id, key)` 只允许一个 `status=ACTIVE`（DB 唯一索引保证） |

## 十七、模板清单（按学科 × 任务）

**术语校验后置检查**（在 `apps/ai` 中实现）：

```python
def check_terminology(text: str, glossary: dict) -> list[TerminologyWarning]:
    """命中禁止用词则返回告警；严重时触发一次修正调用。"""
    warnings = []
    for bad, good in (glossary.get("forbidden") or {}).items():
        if bad in text:
            warnings.append(TerminologyWarning(found=bad, expected=good))
    return warnings
```

## 二十、知识库条目模板（供教师录入参考）

**在知识库编辑器里为每种 `entry_type` 提供预填模板**，降低录入门槛：

| entry_type | 模板提示 |
| --- | --- |
| `CONCEPT` | 定义 + 矢量性/标量性 + 单位 + 与相关概念的区别 |
| `THEOREM` | 内容 + 表达式 + **适用条件（必须逐条列出）** |
| `METHOD` | 适用题型 + 标准步骤 + 常见陷阱 |
| `EXAMPLE` | 题目 + 解答 + 考查点 |
| `COMMON_ERROR` | 错误表述 + 为什么错 + 正确理解（**对干扰项设计最有价值**） |
| `SYLLABUS` | 考纲层次（Ⅰ/Ⅱ）+ 常考题型 + 难度分布 |
| `EXPERIMENT` | 实验目的 + 原理 + 器材 + 步骤 + 数据处理 |
| `REFERENCE` | 教材原文摘录 + 出处 |

**完整示例**（见设计文档附录 E，此处给出可直接导入的 YAML）：

```yaml
# scripts/data/kb_seed_physics.yaml
- entry_type: CONCEPT
  title: 动量
  chapter_path: 第一章 动量守恒定律/第1节 动量
  knowledge_nodes: [动量, 动量的矢量性]
  content: |
    动量是描述物体运动状态的物理量，定义式 p = mv。
    - 矢量性：方向与速度方向相同
    - 单位：kg·m/s
    - 与动能的区别：动量是矢量，动能是标量；p = √(2mEk)
  source_type: TEXTBOOK
  source_ref: {textbook: 人教版, volume: 选择性必修一, chapter: 第一章第1节}

- entry_type: THEOREM
  title: 动量守恒定律
  knowledge_nodes: [动量守恒定律]
  content: |
    内容：如果一个系统不受外力，或者所受外力的矢量和为零，这个系统的总动量保持不变。
    表达式：m1v1 + m2v2 = m1v1' + m2v2'
    适用条件（必须同时满足其一）：
      1. 系统不受外力，或合外力为零
      2. 系统内力远大于外力（如碰撞、爆炸）
      3. 某一方向上合外力为零，则该方向动量守恒
  source_type: TEXTBOOK

- entry_type: COMMON_ERROR
  title: 动量守恒常见错误
  knowledge_nodes: [动量守恒定律]
  content: |
    1. 误把"合外力做功为零"当作动量守恒条件（实际是机械能守恒条件）
    2. 忽略动量的矢量性，直接做代数加减
    3. 碰撞问题中忘记检查是否符合能量不增原则
    4. 把"动量守恒"与"动能守恒"混为一谈（只有弹性碰撞才同时守恒）
  source_type: TEACHER_INPUT
  source_ref: {note: 王老师·动量守恒易错点整理}
```

**导入脚本**：`python scripts/import_kb.py --file scripts/data/kb_seed_physics.yaml --org 1`
