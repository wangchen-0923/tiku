### 需求 2：编辑题目自动回退为草稿，不用提醒

| 项 | 内容 |
| --- | --- |
| 我的初判 | 未考虑，**且与现有设计冲突** |
| 核实结果 | 我的初判**基于错误假设**，已纠正 |
| **关键事实** | `PaperItem` 有 `snapshot_json` 字段。模型注释明确写着：<br>「`PaperItem` 卷面题（**题干快照**，题库改题不影响已发布试卷）」 |
| 结论 | **「已生成试卷」本来就不受题库改题影响** —— 因为卷面用的是快照，不是实时读题库 |
| **所以** | 需求方的要求是**安全的**；现有那层「撤回弹窗」是**基于错误假设加的过度保护** |
| 归属 | `P1-26 题目编辑器` 的**行为修正** |
| 增量 | **0.5 人日**（去掉弹窗 + 补状态提示 + 回归） |

**实施口径（已确认）**：

```
老师点「编辑」 → 若题目不是 DRAFT → 自动置为 DRAFT（不弹窗）
              → 页面上显示一行状态变化（如「已从『已通过』撤回为草稿」）
              → 直接进入编辑态
```

★ **保留状态可见性，但不打断操作**。理由是：静默改状态会让「这道题动过」这件事
无处可见；而**显式一行提示**既快又不丢信息。

★ **要一并修正的过时注释**：`questionbank/services.py` 里那段
「已发布试卷用快照…老师会以为卷子也变了」的说明与实际机制不符，
应改为「卷面用 `snapshot_json`，改题库不影响已发布试卷，因此可自动回退草稿」。

### 需求 3：知识体系 · 知识库管理（新建/编辑/删除 + 上传扩充）

| 子项 | 状态 | 依据 |
| --- | --- | --- |
| 新建条目 | ✅ **已计划并已实现** | `P1-16 知识库条目 CRUD`；后端 `POST /knowledge/entries/` 可用 |
| **编辑条目** | ❌ **未考虑** | 后端 `EntryListCreateView` **只有 `get`/`post`**；`/knowledge/` 路由里**没有单条详情/改/删** |
| **删除条目** | ❌ **未考虑**（只有归档） | 现有 `POST /knowledge/entries/{id}/archive/` 是**归档**（软删），不是删除 |
| 上传知识内容（多格式 + AI 解析） | 🔶 **部分已计划** | `P1-18 知识库文档导入：文档切分（按标题层级）→ 校对归类 → 批量入库`（2.5 人日）<br>★ 但**现有 AI 任务类型里没有「文档解析」**（只有 `gen_explanation` / `generate_question` / `kb_cite` / `embed_text`），需新增 |

**已确认的业务规则（需求方口径）**：

> **该「知识点」下没有任何题目时，才允许改/删该知识点的条目。**

即：**按知识点整体判断**，不是按条目逐条判断。这比逐条判断更保守，也更符合
「知识库是 AI 生题的依据，有点在练就不该动依据」的直觉。

**增量任务**：

| 新任务 | 内容 | 人日 |
| --- | --- | --- |
| **P1-16b** | 知识库条目**更新/删除**接口 + 依赖校验（该知识点下有题则拒） | 1.5 |
| **P1-16c** | 前端：知识库条目**编辑器**（新建/编辑/删除，8 种类型） | 2 |
| **P1-18b** | 知识库文档导入：**.docx / .pdf / .txt** 上传 → 文本抽取 | 1.5 |
| **P1-18c** | AI 文档解析任务（**新增 AI 任务类型** `parse_kb_document`）<br>拆成多条 + 自动归类 8 种类型 + 建议知识点关联 | 2.5 |
| **P1-18d** | 前端：导入向导（上传 → AI 解析预览 → 老师确认 → 批量入库） | 2 |

★ **AI 解析的交互口径（已确认）**：AI **拆成多个条目 + 自动归类**，
**老师确认后入库**（对应 `P1-18` 原文的「校对归类」），不直接入库。

★ **本期与 AI 生题的关系（已确认）**：本轮**只做知识库的管理**，
不改 AI 生题链路 —— 新入库的条目会自动被现有 L1 三路召回检索到。

### 需求 4：组卷 · 总分校验 + 预览 + 导出 + 试卷格式

| 子项 | 状态 | 依据 |
| --- | --- | --- |
| 预览 | ✅ **已计划** | `POST /papers/{id}/preview/`（05 文档）+ `P1-60 预览（HTML）` |
| 导出 PDF / Word | ✅ **已计划** | `GET /papers/{id}/export/`（05 文档「导出 PDF / Word」）+ `P1-60` |
| 前端预览与导出 | ✅ **已计划** | `P1-62 前端：试卷预览与导出`（2 人日） |
| **期望总分校验** | ❌ **未考虑** | 全库搜 `期望总分` / `target_total` / `总分校验` → **0 命中**。<br>`Paper.total_score` 现在的语义是**「题目分值累加算出来的」**（`Paper.recalc_total()`） |
| **选项排列方式**（1列4排/2列2排/4列1排） | ❌ **未考虑** | `option_order` 是**选项乱序**（防作弊打乱 A/B/C/D 顺序），**不是排列方式** |

- **总分校验交互**：填「期望总分」→ 系统**按题型配额建议配分** → 老师**可手改** → **定稿时校验**是否相等，不等则拦住。
- **选项排列方式的作用域**：**这是「生成试卷时」选择题选项的排版方式**（不是答题卡的）。
- **试卷格式参数存放**：**两者都要** —— 预置样式（开箱即用）+ 允许自定义保存（可复用）。

**增量任务**：

| 新任务 | 内容 | 人日 |

| **P1-60b** | `layout_config` 落地：页边距 / 行距 / 字号 / **选项排列方式**<br>（`1列4排` / `2列2排` / `4列1排`）| 2 |
| **P1-60c** | 试卷样式库：预置样式 + 保存自定义样式（字段复用 `Paper.layout_config`）| 1.5 |
| **P1-62b** | 前端：总分设置与校验提示 + 试卷格式面板（实时预览）| 2 |

★ **`Paper.target_total_score` 是新字段**，需要迁移。
★ **「选项排列方式」要在排版引擎里实现**三种排布：
`1列4排` = 一行 1 组题、纵向 4 题；`2列2排` = 一行 2 组、纵向 2 题；
`4列1排` = 一行 4 组、纵向 1 题。
