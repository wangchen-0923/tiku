### 1.1 六项任务与里程碑

| 顺序 | 任务 | 工期 | 依赖 | 里程碑 |
| --- | --- | --- | --- | --- |
| 1 | 主观题阅卷（切图、自动下一位、评语） | 10 人日 | 无 | M1 |
| 2 | 状态机最小收口 + 幂等/重试 | 4 人日 | 与 1 并行 | M1 |
| 3 | OMR 自检与样本回归、低分辨率兜底 | 6 人日 | 无 | M2 |
| 4 | 题目分析报表 | 4 人日 | 与 3 并行 | M2 |

- M1（第 2 周末）：主观题可以按题连续批完，状态不再反复。
- M2（第 3 周末）：线下扫描有自检与样本回归，题目分析能出报表。
- M3（第 5 周末）：知识点标签覆盖率达到 90%，覆盖体检可以开始。
- M4（第 6 周末）：组卷发布前有覆盖与难度体检，全量回归通过。

### 1.2 完成定义（DoD）

每一项任务完成，必须同时满足：

1. 迁移可回滚（`migrate <app> <prev>` 能退回）。
2. 接口有类型定义（前端 TS）与错误码。
3. 新增/修改路径有回归脚本，原有用例不减少。
4. 有审计日志（谁、何时、改了什么）。
5. 文档更新：本文对应章节 + `docs/开发进度记录.md`。
6. 有一条可复现的演示命令或演示数据。

### 1.3 架构原则

1. **单一事实源**：几何只在 `apps/sheet/layout.py`；知识点关系只在 `QuestionKnowledge`；状态流转只在状态机入口。
2. **状态唯一入口**：任何状态字段不得在视图层直接赋值，必须走 `transition()`。
3. **幂等优先**：上传、识别、评分、交卷都要能用同一个请求重复调用而不产生第二条数据。
4. **快照优先**：试卷、答题卡、评分依据都用发布时的快照，不回读实时题目。
5. **AI 只给建议**：任何 AI 输出必须带置信度、来源与人工确认状态。
6. **同步兜底**：Celery 未接线前，关键路径必须能同步完成；异步只是加速，不是唯一路径。

## 二、任务一：主观题阅卷

### 2.1 目标与非目标

目标：

- 识别成功后，把每道主观题的答题区从整页校正图上裁下来单独保存。
- 教师主观题阅卷：选题 → 逐个学生看切图 → 给分 → 自动下一位。
- 全部批完，学生状态与作业统计自动收口。

非目标（本阶段不做）：

- 评分量表（rubric）、双评仲裁、AI 评分建议。
- 学生端查看切图或申诉。
- 主观题自动识别文字。

### 2.2 数据模型

新增 `apps/omr/models.py::SubjectiveCrop`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| org | FK Org | 机构隔离 |
| assignment | FK Assignment | 所属作业 |
| scan_card | FK ScanCard | 来源卡 |
| student | FK User | 已归属学生 |
| paper_item | FK PaperItem | 对应卷面题 |
| sheet_seq | int | 卷面题号 |
| kind | str | ANSWER / ESSAY / FILL_BLANK |
| page_no | int | 卡内页码 |
| part_index | int | 同题多段时的段号，从 1 开始 |
| part_count | int | 同题总段数 |
| rect_json | JSON | `{x_mm, y_mm, w_mm, h_mm}` |
| asset | FK Asset | 切图文件 |
| template_version | int | 生成时的模板版本 |
| created_at / updated_at | datetime | |

约束与索引：

- 唯一：`(scan_card, paper_item, part_index)`
- 索引：`(assignment, paper_item)`、`(assignment, student)`

迁移要求：`makemigrations omr` 生成，`migrate` 可在空表上执行；回滚只删表，不动既有数据。

### 2.3 切图服务

新增 `apps/omr/crops.py`：

```python
def generate_crops_for_card(org_id: int, card_id: int) -> list[SubjectiveCrop]:
    ...
```

步骤：

1. 取 `ScanCard.display_asset`；为空时调用现有 display 服务生成整页校正图；仍失败返回空并记 `PAPER.CROP_NO_DISPLAY` 告警。
2. 按 `card.page_no` 取 `layout_json.pages[page_no-1]`。
3. 按块类型取矩形：
   - `ANSWER`：`page.subjective` 中 `seq` 对应的 `x_mm / y_mm / w_mm / h_mm`。
   - `ESSAY`：`page.essays` 中 `seq` 对应整块；跨页时每页一段，`part_index` 递增。
   - `FILL_BLANK`：`page.fill_blanks` 中该题所有行的外接矩形（取 `x1_mm` 最小、`x2_mm` 最大、`y_mm` 最小与最大）。
4. 四周各留 2 mm；矩形夹到 `[0, page_width_mm] × [0, page_height_mm]`。
5. 像素换算：`scale = asset.width / page_width_mm`；裁图。
6. 统一存 JPEG 质量 85；宽度超过 2000 px 时等比缩小。Asset kind=`SUBJECTIVE_CROP`，文件名 `card-{id}-q{seq}-p{page}-{part}.jpg`。
7. 幂等：同 `(scan_card, paper_item, part_index)` 且 `template_version` 相同则跳过；重新识别时先删旧切图。
8. 切图宽或高小于 80 px 记告警，不阻断。

触发点：

- `apps/omr/scan_service.py::recognize_batch`：卡片 `AUTO_OK` 且学生已归属。
- `apps/omr/services.py::review_card`：人工复核写回后。
- 阅卷接口：发现缺切图时按需生成。

补历史数据：

```powershell
python manage.py backfill_subjective_crops --assignment 399
python manage.py backfill_subjective_crops --all --limit 500
```

命令要支持 `--dry-run`、`--batch-size`，输出成功/失败/跳过数量。

### 2.4 接口

统一前缀 `/api/v1/grading`，权限 `IsTeacherOrAbove`，机构隔离。

1. `GET /assignments/{id}/review/items/`

```json
{
  "items": [
    {
      "paper_item_id": 101,
      "seq": 11,
      "type": "FILL_BLANK",
      "section_title": "三、填空题",
      "max_score": 4,
      "total_students": 45,
      "graded": 30,
      "pending": 15
    }
  ],
  "overall": {"graded": 120, "total": 225}
}
```

只统计 `assignment_student.status in (SUBMITTED, SCANNED)`；按 `seq` 升序。

2. `GET /assignments/{id}/review/items/{paper_item_id}/students/?filter=pending&page=1&page_size=50`

```json
{
  "items": [
    {
      "student_id": 612,
      "student_no": "25251422",
      "student_name": "张三",
      "submitted_at": "2026-10-19T03:44:45Z",
      "crop_asset_id": 901,
      "rect": {"x_mm": 15, "y_mm": 120, "w_mm": 180, "h_mm": 40},
      "page_no": 1,
      "part_index": 1,
      "has_crop": true,
      "score": null,
      "score_state": "",
      "comment": "",
      "graded": false
    }
  ],
  "total": 15
}
```

排序：`student_no` 升序。`filter=pending` 时排除已评分的。

3. `POST /assignments/{id}/review/score/`

```json
{"student_id": 612, "paper_item_id": 101, "score": 3.5, "reason": "步骤完整，结论正确"}
```

- 复用 `GradingService` 现有 manual-score 逻辑，不另写判定。
- 分数范围 `0 ≤ score ≤ max_score`；步长 0.5 由前端约束，后端只校验范围。
- 返回：

```json
{
  "score_id": 5001,
  "state": "MANUAL_ENTERED",
  "item_progress": {"graded": 31, "total": 45},
  "next_student": {"student_id": 613, "student_no": "25251426", "student_name": "李四"}
}
```

4. `GET /assignments/{id}/review/summary/`

返回整卷主观题完成情况，用于全部批完后的汇总页。

### 2.5 页面

路由：`/assignments/:id/review`，名称 `AssignmentReview`。
入口：批改工作台顶部「主观题阅卷」按钮（**唯一入口**）。
作业详情页不放入口——改卷动线是「先进批改，再切到按题」，
详情页再放一个会让老师分不清该点哪个。

三栏布局：

- 左：题目列表（题号、题型、满分、已批/总数、进度条）；当前题高亮；顶部整卷进度。
- 中：
  - 顶部：学生姓名、学号、第 x / y 份。
  - 题干：卷面快照 `stem_text`，保留换行。
  - 切图：默认适应宽度；滚轮缩放、拖拽；右上角“看整页”打开整页图并半透明高亮当前 `rect`。
  - 参考答案：可折叠，默认收起。
  - 分数：快捷“满分 / 一半 / 0” + 数字输入（步长 0.5）。
  - 评语：最多 500 字，可选。
  - 操作：保存并下一位、跳过、上一位、下一位。
- 右：学生列表（学号、姓名、已批/未批），点击跳转；“只看未批”开关。

自动切换：

1. 保存成功 → 用返回的 `next_student`。
2. 没有 → 下一道仍有未批的题。
3. 都没有 → 汇总页。

键盘：

| 键 | 行为 |
| --- | --- |
| 数字、小数点 | 输入分数 |
| Enter | 保存并下一位 |
| ← / → | 上一位 / 下一位 |
| S | 跳过 |
| A | 切换参考答案 |
| Esc | 关闭整页图 |

输入框聚焦时数字键不触发全局快捷键。

性能：

- 预取下一份切图。
- 学生列表分页 50，切换题目重新拉。
- 图片用 `fetchBlob` + `URL.createObjectURL`，离开页面 `revoke`。

### 2.6 状态与统计

1. 评分沿用 `ScoreResult`：首次 `MANUAL_ENTERED`，修改已存在评分 `TEACHER_MODIFIED`，`method=MANUAL`，`reason` 存评语。
2. `GradingSelector.roster` 的 `grading_state`：
   - 所有主观题都有最终评分，且客观题无待批 → `DONE`
   - 其余已交卷 → `PENDING_MANUAL`
3. 作业详情“待批改”与批改工作台统计必须与阅卷页一致。
4. 每次保存返回 `item_progress`，前端即时更新，不整页刷新。

### 2.7 边界

| 场景 | 处理 |
| --- | --- |
| 学生未归属 / 识别失败 / 卡作废 | 无切图，默认未批列表不显示；全部列表提示“无切图，无法阅卷” |
| 多页作文 | 按 `part_index` 展示，一次评分覆盖整题 |
| 重复给分 | 视为修改，不新增记录 |
| 两位老师同时批改 | 最后提交为准；返回 `updated_at`，前端提示是否覆盖 |
| 切图缺失 | 展示整页图并定位到该题区域，不阻断评分 |
| 分数为 0 | 允许保存，评语可空 |

### 2.8 测试与验收

单测：

- 切图几何：给定布局与资产尺寸，`rect → 像素` 正确；越界被夹住。
- 多段作文：`part_index` 与 `part_count` 正确。
- 幂等：重复生成不新增记录；模板版本变化后重建。

接口：

- 题目清单只含主观题；`max_score` 与卷面一致。
- 学生列表排序、筛选、分页正确。
- 评分越界 400；重复评分状态为 `TEACHER_MODIFIED`。

端到端：

1. 45 人 × 5 题，连续批完，自动下一位。
2. 批改工作台待批改数实时下降，全部批完为 0。
3. 历史卡 `backfill` 后可进入阅卷。

回归：

```powershell

python scripts/verify_sheet_scan_e2e.py
python scripts/verify_sheet_assignment_flow.py
```

### 2.9 风险

- 切图坐标与实物偏差：用 5 张真实卡人工抽检，误差 >2mm 即回退检查 layout。
- 图片体积：单场 45×5 约 50MB，需在 media 配置容量告警。
- 评分并发：先做“最后写入 + 提示”，不做锁。

## 三、任务二：状态机最小收口

### 3.1 范围

只收口四个实体，不做全量框架：

- `ScanBatch`
- `ScanCard`
- `AssignmentStudent`
- `ScoreResult`

`Assignment` 的状态（DRAFT/PUBLISHED/CLOSED/ARCHIVED）沿用现状，不纳入本期。

### 3.2 状态与转移

| 实体 | 允许转移 |
| --- | --- |
| ScanBatch | UPLOADING → PROCESSING → COMPLETED / WAITING_REVIEW / FAILED；FAILED → PROCESSING（重试） |
| ScanCard | PENDING → AUTO_OK / NEEDS_REVIEW / FAILED；NEEDS_REVIEW → REVIEWED / VOID；AUTO_OK → REVIEWED / VOID；FAILED → PENDING（重扫）；任意 → VOID（终态） |
| AssignmentStudent | NOT_STARTED → IN_PROGRESS → SUBMITTED / SCANNED；SUBMITTED ↔ SCANNED（扫描覆盖，不降级）；任意 → ABSENT；不回到 NOT_STARTED |
| ScoreResult | PENDING → AUTO_GRADED / NEEDS_REVIEW / MANUAL_ENTERED；NEEDS_REVIEW → TEACHER_CONFIRMED / TEACHER_MODIFIED；AUTO_GRADED → TEACHER_MODIFIED；任意 → VOID |

规则：

- `SCANNED` 不得退回 `SUBMITTED`。
- `VOID` 是终态，除审计外不可再流转。
- 非法转移返回 409，错误码 `COMMON.INVALID_STATE_TRANSITION`，消息里给出当前状态与目标状态。

### 3.3 实现

新增 `apps/common/state.py`：

```python
def transition(obj, to_state: str, *, actor_id=None, reason="", extra=None):
    """唯一状态入口：校验、赋值、保存、审计。"""
```

- 维护 `TRANSITIONS = {Model: {from: {to, ...}}}`。
- 内部写 `audit_log.record`，记录 `from`、`to`、`actor`、`reason`。
- 调用方只能用它，禁止 `obj.status = "..."` 直写；用 `grep` 在 CI 里做静态检查（排除迁移与测试）。

### 3.4 幂等与重试

| 操作 | 幂等键 | 行为 |
| --- | --- | --- |
| 上传扫描件 | `assignment_id + sha256` | 已存在则重置为 PENDING 并重新识别，不新建卡 |
| 提交识别 | `batch_id + PROCESSING` | 已在处理则直接返回当前进度 |
| 评分 | `assignment + student + paper_item` | 第二次为修改，不新增 |
| 交卷 | `assignment + student` | 已交卷直接返回，不重复写时间 |

重试：

- 识别失败：批次 FAILED，卡片 FAILED，可点“重试”；指数退避最多 3 次。
- 评分写失败：事务回滚，返回可重试错误码。
- 所有重试写审计，避免无限重试。

### 3.5 测试

- 转移矩阵：每个合法转移成功、每个非法转移 409。
- 幂等：同一请求连续两次，数据库记录数不变。
- 并发：两个请求同时提交识别，只有一个进入 PROCESSING。
- 审计：每次转移都有记录。

### 3.6 验收

- 扫描批次不再永久停在 PENDING/PROCESSING。
- 学生状态在线上/线下切换时不再回退。
- 评分重复提交不产生第二条。
- 新的状态直写被静态检查拦住。

## 四、任务三：OMR 自检与样本回归

### 4.1 目标

把“这张卡识别不了”从口头问题变成可复现、可定位、可回归的工程问题。

### 4.2 样本库

目录：`server/apps/omr/tests/fixtures/`（与识别测试共用一套，不另建目录）

| 样本 | 现状 | 用途 |
| --- | --- | --- |
| `photo_3024_pencil.png` | ✅ 已有（真实上传卡原图） | 高分辨率真实铅笔；答案 `1C 2C 3A 4C 5C 6A 7B 8A 9B 10A`、学号 `24251417` |
| `photo_1280_tilted.png` | ✅ 已有（真实上传卡原图） | 低分辨率 + 纸面倾斜；只断言定位与状态 |
| `a5_scaled.png` | ✅ 已有（合成） | A4 设计缩到 70.7% 打印；15 题答案已知 |
| `synthetic_a4_300dpi.png` | 由 `scripts/gen_omr_fixtures.py` 现场生成 | 合成卡基线 |
| `photo_blank.png` / `photo_missing_anchor.png` / `photo_dark.png` | 待补（需要真实拍摄）：前两张可用同一张卡抹掉涂点/裁掉一角合成 | 空白卡 / 缺角 / 光照不足 |

每个样本配一个 `<name>.expect.json`：学号（可空=不断言）、逐题答案
（可只写部分题）、期望状态（AUTO_OK / NEEDS_REVIEW / FAILED）。
判定口径是**三者全中**才通过：「答案对了但状态是 NEEDS_REVIEW」不算通过。

### 4.3 自检脚本

新增 `scripts/omr_selfcheck.py`：

```powershell
# 默认读仓库自带样本（server/apps/omr/tests/fixtures，3 张 + *.expect.json）
python scripts/omr_selfcheck.py --report reports/omr.html
# 只调一张
python scripts/omr_selfcheck.py --debug-card photo_1280_tilted
```

输出：

- 每张样本：定位成功/失败、四角坐标、学号、逐题答案、置信度、状态。
- 汇总：通过率、失败分类（定位、页标、学号、涂点、分辨率）。
- 失败时保存调试图：`artifacts/omr-debug/{name}/-anchors.png`、`-warped.png`、`-samples.txt`。

要求：退出码非 0 表示有失败，可直接接 CI。
★ 依赖缺失时退出码 3 并说明缺什么（不要静默跳过）。

样本来源与 `*.expect.json` 字段见
`server/apps/omr/tests/fixtures/README.md`：三张样本分别是
真实铅笔实拍（3024px）、倾斜手机照（1280px）、A4 设计按 A5 打印的合成卡。

### 4.4 调试图

`--debug-card <card_id>` 生成三张图：

1. 原图 + 检测到的四角与期望四角。
2. 校正后整页图 + 每题选项采样框。
3. 每题每个选项的填充分数条。

保存到 `artifacts/omr-debug/{card_id}/`，不进入 media。

### 4.5 阈值标定

新增 `scripts/omr_calibrate.py`：

- 读取样本的每个选项填充分数与人工标注。
- 统计已涂/未涂分布，输出建议阈值与分离度。
- 结果写入 `threshold_config` 快照，并在文档记录样本量与日期。

规则：

- 样本量 <30 时只输出建议，不自动改线上阈值。
- 阈值变更必须带版本号，旧卡按旧阈值识别。

### 4.6 低分辨率兜底

- 长边 <1000 px：告警但继续。
- 长边 <600 px：直接 FAILED，提示“分辨率过低，请 300dpi 扫描或提高拍照像素”。
- 失败消息必须包含：图片尺寸、候选数、失败阶段。

### 4.7 验收

- 合成样本 100% 通过。
- 真实样本 ≥20 张，通过率 ≥95%，失败样本有明确分类。
- 1280 px 照片能识别；A5 等比缩放能识别。
- 自检脚本能在 5 分钟内跑完。

## 五、任务四：题目分析报表

### 5.1 指标

对每道题、每场考试计算：

| 指标 | 公式/口径 |
| --- | --- |
| 作答人数 n | 有评分的作答数 |
| 平均分 | `mean(score)` |
| 难度 p | `mean(score) / max_score`（0–1） |
| 区分度 D | 总分前 27% 的 p 减后 27% 的 p |
| 选项分布 | 每个选项被选次数与占比（选择题） |
| 点二列相关 | 题目得分与总分的相关系数 |
| 零选择干扰项 | 选中次数为 0 的选项 |

样本量保护：

- n < 30：只展示，不判定“好/差”，标注“样本不足”。
- 难度与区分度累计 2–3 场后再写回题目元数据。

### 5.2 存储

新增 `apps/analytics/models.py::ItemStat`：

- org、assignment、paper_item、n、mean、p、d、point_biserial、option_counts、sample_sufficient、created_at。
- 唯一：`assignment + paper_item`。

新增 `QuestionStat`（题目长期校准）：

- org、question、exam_count、total_n、p_avg、d_avg、updated_at。
- 评分定稿后增量更新，不覆盖历史。

### 5.3 接口

- `GET /api/v1/analytics/assignments/{id}/items/`：逐题指标。
- `GET /api/v1/analytics/questions/{id}/stats/`：题目历史校准。
- `GET /api/v1/analytics/assignments/{id}/items/export/`：CSV。

### 5.4 页面

作业学情页新增“题目分析”页签：

- 表：题号、题型、n、平均分、p、D、点二列、零选择项。
- 颜色：p 过低/过高、D <0.2 标红。
- 选中一行展开选项分布条形图。
- 导出 CSV。

### 5.5 验收

- 一场已有成绩的考试能看到逐题指标。
- 样本不足有明确标识。
- CSV 与页面数字一致。
- 连续 3 场后 `QuestionStat` 有累计值。

## 六、任务五：知识点标签升级

### 6.1 现状与目标

现状：`KnowledgeNode` 树 + `QuestionKnowledge` 关联，已有 44 个节点、1944 道题。
目标：标签体系可维护、可合并、可追溯，覆盖率达到 90%，为覆盖体检与 AI 出题提供依据。

### 6.2 模型

新增：

- `KnowledgeAlias`：别名、同义词、错写，指向节点。
- `KnowledgeMergeLog`：合并前后 id、操作人、时间、原因。
- `QuestionKnowledge` 增加：`source`（MANUAL / AI / IMPORT）、`confidence`、`review_state`（PENDING / CONFIRMED / REJECTED）。

规则：

- 节点 id 稳定，不删除；废弃用 `deprecated_at`。
- 合并只改引用，不物理删除。
- AI 标注默认 `PENDING`，教师确认后 `CONFIRMED` 才计入覆盖统计。

### 6.3 迁移

1. 先建别名表与字段，双写。
2. 导出当前标签分布，人工确认合并清单。
3. 执行合并脚本，保留 `KnowledgeMergeLog`。
4. 回滚脚本：按 log 反向恢复引用。

### 6.4 标注流程

1. 规则优先：题干关键词、教材章节映射、题型。
2. AI 兜底：用知识库内容做检索，输出候选节点与置信度。
3. 教师确认队列：按置信度升序，批量确认/驳回。
4. 覆盖率报表：按章节、节点统计已标注题数、主标签率、冲突率。

### 6.5 验收

- 题目标注覆盖率 ≥90%，主标签率 ≥85%。
- 任意节点可查别名与合并历史。
- AI 标注不直接进统计，必须人工确认。
- 回滚脚本在测试库验证通过。

## 七、任务六：组卷覆盖体检

### 7.1 体检项

发布前对试卷计算：

1. 知识点覆盖：每个节点的题数、分值、占比。
2. 蓝图对比：与 `compose_config` 的目标配额比较，输出缺口与超出。
3. 难度分布：按题目校准难度分档，比较目标分布。
4. 题型与分值：题型结构、总分、各题分值是否与配置一致。
5. 重复题：题干哈希 + 相似度，标出重复与近似重复。
6. 超纲题：知识点不在本课程/本章范围。

### 7.2 规则

- 阻断：总分不符、精确重复题、必需节点零覆盖。
- 告警：难度偏斜、近似重复、单节点占比过高。
- 允许教师填写理由后强制发布，理由入审计。

### 7.3 接口与页面

- `GET /api/v1/paper/papers/{id}/coverage/`：体检结果。
- 组卷页“发布前体检”面板：
  - 顶部总分与题量对照。
  - 知识点覆盖热力图（章节 × 节点）。
  - 缺口清单与“去补题”按钮。
  - 难度分布柱状图。
  - 重复题列表。
- 发布按钮：有阻断项时禁用；有告警时二次确认。

### 7.4 验收

- 构造缺知识点、总分不符、重复题的试卷，均被正确拦截。
- 补题后体检通过，可发布。
- 强制发布有审计记录。
- 体检结果与题目分析使用同一套知识点口径。

## 九、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 状态机改造触碰面广 | 旧路径被阻断 | 先只做四个实体；旧代码路径保留一个版本；灰度开关 |
| 知识点迁移数据错乱 | 覆盖统计失真 | 双写、别名、合并日志、回滚脚本 |
| 切图坐标偏差 | 阅卷看不到完整答案 | 视觉抽检 + 误差告警 + 整页兜底 |
| 真实样本不足 | 阈值不可信 | 合成样本 + 少量真实样本；标注样本量 |
| 并发评分覆盖 | 分数丢失 | 返回 updated_at，提示覆盖；后续再加锁 |
| 时间估算偏乐观 | 里程碑延期 | 每项预留 20% buffer；M1/M2 优先 |

回滚原则：

- 迁移必须可逆；不可逆的迁移要先备份表。
- 新增字段先双写，确认无问题再切读。
- 功能用开关控制，默认关闭，验收后打开。

- QTI 全兼容、SCORM。
- 双评与仲裁。
- 监考、人脸识别、屏幕锁定。
