| 估工准确性 | 阶段二 8 周 / ~150 人日 | 后端已投入远超；**测试成本被低估**（原 `P4-08` 估 2 人日，实际 31 套 2299 项） |

## 九、M2 实施记录（2026-10-09）

**已完成**：题目编辑器（详情抽屉 / 编辑表单 / 新建抽屉）+ 题库列表改造。

**顺带修掉 3 个真缺陷**（都不在原计划里，且**2299 项测试全绿时它们依然存在**）：

| # | 缺陷 | 后果 | 为什么测试没抓到 |
| --- | --- | --- | --- |
| 1 | `PATCH /questions/{id}/` 带 `options` **必 500** | 改选项完全不可用 | 既有 API 测试的 PATCH **只测 `stem_text`** |
| 2 | 改选项**静默清空** `is_correct` | 改一次选项 → 该题**所有答案判错** | 同上；且它不报错 |

| 4 | `difficulty_source` 模型默认值污染 1944 行 | 全库显示「人工标注」，无法分辨标注过的题 | 数据问题，非代码 |

**验证**：`scripts/verify_questionbank_h5.py`（**104 项**）——逐字段对齐 +
新建→编辑→审核→删除闭环 + `difficulty_manual` 通路 + 判断题布尔答案。
连跑两遍题库数量稳定在 1944（零残留）。

**决策 7 的通路已打开，且已在界面上显性化**：

- 编辑器里可改 `difficulty_manual`，实测 `difficulty_effective` 与
  `difficulty_source` 跟着变（`MANUAL_OVERRIDE`）——
  **只要开始补标注，个性化练习就有机会生成**。
- 新增 `QuestionSelector.difficulty_health()`，并把结果挂在
  `/questions/stats/` 的 `difficulty` 字段上。题库页顶部**直接说明**：
  「可组卷 1944 道，其中 **0 道**有人工难度标注；难度档位只有 **1 种**」，
  并解释「个性化练习按 [1.0, 2.0] 取题，全库 3.00 永远落不进区间」。

★★ 为什么必须显性化：练习生成失败时只返回
`PRACTICE.BANK_INSUFFICIENT`，**从报错看不出根因是数据而不是算法**。
把根因做成可判定数字摆出来，老师才知道**要去补**。

★ 实测现状（2026-10-09）：

| --- | --- |
| 可组卷题数 | 1944 |

| `difficulty_ai` / `difficulty_stat` 有值 | **0 / 0** |
| `difficulty_effective = 3.00` | **1944（全部）** |
| `difficulty_band` 种类数 | **1**（全 `MEDIUM`） |

★ 但**补 1944 道题的难度仍需你定方案**（全人工不现实）。建议：
先用启发式（题干长度 / 章节顺序 / 题型）给初值，再由教研在编辑器里抽检修正。

## 十、M2 收口结论（2026-10-09）

**M2 里程碑出口判据「可手工录题并打标」—— 四条全部实测满足。**

| 判据 | 实测证据 |
| --- | --- |
| **可手工录题** | 选择题（含 4 选项 + 正确答案 + 难度）与填空题（2 空）均 201 落 `DRAFT` |
| **可检索** | `keyword` 精确命中；关键词 + 题型 / 状态 / 知识点组合筛选均正确 |
| **可打标** | `node_ids` 关联写入并带出 `node_name` / `node_code` / `is_primary`；按知识点能检索到 |
| **可审核** | `action=APPROVE` → `APPROVED` + `reviewed_at`；审核后进 `usable_for_paper` 集合 |

验证脚本：`scripts/verify_m2_exit.py`（**32 项**），跑完题库回到基线 1944。

**交付的界面**：

- `/questions` 题库列表（筛选 / 批量审核 / 深链 `?open=&nodeId=`）
- 题目详情抽屉（题干 / 选项 / 答案 / 解析 / 知识点 / 配图 / 审核）
- 题目编辑表单（含**难度标注通路**）
- 新建题目抽屉（题型分支 + 三层去重）
- `/knowledge` 知识体系（知识点树 + 知识库条目 + 健康度运营台）

**本轮修掉的缺陷（7 个，全部在 2299 项测试全绿时依然存在）**：

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | `PATCH` 带 `options` 必 500 | 改选项完全不可用 |
| 2 | 改选项静默清空 `is_correct` | 改一次选项 → 该题所有答案判错 |
| 3 | 前端搜索传 `search`（后端读 `keyword`） | 搜索框一直返回全部 1944 题 |
| 4 | `only_usable=true` 时 `keyword` 被忽略 | 「只显示可组卷的题」状态下搜索坏 |
| 5 | `difficulty_source` 默认值污染 1944 行 | 全库显示「人工标注」，无法分辨 |
| 6 | `revise` 端点缺失 | 错误信息让调它，但**没有这个接口** → 已审核的题改不了 |
| 7 | `el-tree` 缺 `node-key` 的 id | 知识树静默不渲染 |

**★ 决策 7 的通路**：编辑器里可改 `difficulty_manual`，
实测 `difficulty_effective` 与 `difficulty_source` 跟着变
（`MANUAL_OVERRIDE`）。**但补 1944 道题的难度仍需你定方案**
（全人工不现实；建议启发式初值 + 教研抽检修正）。
