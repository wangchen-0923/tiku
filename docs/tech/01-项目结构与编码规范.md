**每个业务模块的标准文件**：`models.py` / `services.py` / `selectors.py` / `serializers.py` / `views.py` / `urls.py` / `tasks.py` / `tests/`。

**分层职责（强制）**：

| 文件 | 职责 | 禁止 |
| --- | --- | --- |
| `models.py` | 表结构、字段校验、模型级方法、Manager | 禁止跨表业务逻辑、禁止调外部服务 |
| `selectors.py` | 只读查询，返回 QuerySet 或 dataclass | 禁止写操作 |
| `services.py` | 业务写操作，事务边界 | 禁止解析 request、禁止返回 Response |
| `views.py` | 参数校验、权限、调 Service/Selector、序列化 | 禁止业务计算、禁止直接 ORM 写 |
| `tasks.py` | Celery 包装，只做编排 | 禁止长事务、禁止业务逻辑（逻辑在 services） |
| `serializers.py` | 输入校验 + 输出序列化 | 禁止业务规则 |

## 四、Python 编码规范

### 4.1 工具链

| 工具 | 配置 | 要求 |
| --- | --- | --- |
| `ruff` | `pyproject.toml` | 行长 100，启用 E/F/I/N/UP/B/C4/SIM/ARG |
| `black` | 行长 100 | 提交前必须格式化 |
| `mypy` | 核心模块 strict | `apps/common`、`apps/omr`、`apps/grading`、`apps/ai` |
| `pytest` + `pytest-django` | | |
| `import-linter` | `.importlinter` | 依赖方向 |

### 4.2 命名与风格

```python
# ✅ 正确
class FigureConfirmService:
    """配图逐图确认服务。"""

    def confirm(self, figure_id: int, teacher_id: int, method: ConfirmMethod) -> QuestionImage:
        ...

# ❌ 错误：动词名词混用、无类型标注、函数里做业务
def doConfirm(id, t):
    ...
```

| 规则 | 说明 |
| --- | --- |
| 全量类型标注 | 新增函数必须有参数与返回值标注；`mypy` 严格模块必须通过 |
| 不写 `**kwargs` 透传 | 会丢失类型信息与可读性 |
| 常量集中 | 阈值与枚举放 `apps/common/constants.py` 或各模块 `constants.py`，**不在函数内写魔法数字** |
| 异常 | 业务异常继承 `apps.common.exceptions.BusinessError`，携带错误码 |
| 早返回 | 避免深层嵌套，校验失败立即 raise 或 return |
| 列表推导 | 简单转换用推导，含副作用或复杂条件用循环 |
| 时间 | 一律用 `django.utils.timezone.now()`，**禁止 `datetime.now()`** |

### 4.3 Service 写法模板

```python
# apps/grading/services.py
from django.db import transaction
from apps.common.exceptions import BusinessError
from apps.common.error_codes import GRADING_SCORE_EXCEED_MAX

@transaction.atomic
def enter_subjective_score(
    *,
    assignment_id: int,
    student_id: int,
    paper_item_id: int,
    score: Decimal,
    operator_id: int,
    reason: str | None = None,
) -> ScoreResult:
    """
    录入一道主观题的分数（逐题录分）。

    契约：
      - score 不得超过该题配分，否则抛 GRADING.SCORE_EXCEED_MAX
      - 幂等：同一 (assignment, student, paper_item) 覆盖写，旧值记入 audit
      - 触发下游重算（合并去抖）
    """
    item = PaperItemSelector.get(paper_item_id)
    if score > item.score:
        raise BusinessError(GRADING_SCORE_EXCEED_MAX, detail={"max": str(item.score)})

    result, created = ScoreResult.objects.update_or_create(
        assignment_id=assignment_id,
        student_id=student_id,
        paper_item_id=paper_item_id,
        defaults={
            "score": score,
            "max_score": item.score,
            "method": ScoreMethod.MANUAL,
            "state": ScoreState.MANUAL_ENTERED,
            "graded_by_id": operator_id,
            "graded_at": timezone.now(),
        },
    )
    if not created:
        audit_log.record("score_result.modify", result, operator_id, reason=reason)
    schedule_recompute(assignment_id, student_id)     # 去抖合并
    return result
```

**要点**：关键字参数、docstring 说明契约、先校验后写、幂等用 `update_or_create`、写审计、触发重算。

### 4.4 禁止事项

| 禁止 | 原因 |
| --- | --- |
| 在 View 里写业务逻辑 | 无法复用、无法测试 |
| 直接 import 厂商 SDK（除 `apps/ai/providers`） | 破坏可替换性 |
| 在函数内写阈值数字 | 机构级覆盖失效 |
| 跨模块 `Model.objects` 直接查询 | 破坏模块边界；用对方 Selector |
| `datetime.now()` | 时区不一致 |
| 在 Celery 任务里传 Model 实例 | 反序列化失败 |
| `print()` 调试 | 用 logger；CI 检查 |
| 裸 `except:` | 吞异常 |
| 硬编码对象存储路径 | 用 `media.services` |

## 六、Git 工作流

### 6.1 分支模型

| 分支 | 说明 |
| --- | --- |
| `main` | 生产可发布，受保护，禁止直接 push |
| `develop` | 集成分支，CI 全绿可合并 |
| `feat/<模块>-<简述>` | 功能分支，如 `feat/omr-student-no` |
| `fix/<模块>-<简述>` | 缺陷修复 |
| `hotfix/<简述>` | 生产紧急修复，从 `main` 拉，修完双向合并 |
| `docs/<简述>` | 文档 |

### 6.2 提交信息规范（Conventional Commits）

```
<type>(<scope>): <subject>

[body]

[footer]
```

| type | 说明 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `refactor` | 重构（无行为变化） |
| `perf` | 性能优化 |
| `test` | 测试 |
| `docs` | 文档 |
| `chore` | 构建/依赖/配置 |
| `migration` | 数据库迁移（**必须单独提交**） |

`scope` 取值 = 模块名：`omr` / `ingest` / `figure` / `paper` / `grading` / `analytics` / `practice` / `ai` / `kb` / `sheet` / `web` / `deploy`。

**示例**：

```
feat(omr): 支持学号位数 1-12 位自由配置与多行排布

- student_no_bubble() 按 layout 计算行列
- 新增排版约束校验，超宽时给出具体建议
- 单元测试覆盖 pos=per_row 跨行边界

Refs: #142
```

**要求**：
- 迁移文件必须独立提交（`migration(db): 新增 question_image 确认字段`），便于回滚与 review。
- 一个 PR 只做一件事；超过 500 行改动需说明理由。
- 提交信息必须能解释"为什么"，不只是"做了什么"。
