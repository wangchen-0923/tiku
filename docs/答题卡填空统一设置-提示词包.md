## 4. 五个必须先定的口径

### ① 每空默认分值到底影响什么（**最重要**）

`judge.py` 判填空题是**每空等分**，不读 `blank_scores`。所以"每空默认分值"目前只影响：
- 卷面印出来的分值标注；
- `section.score = sum(blank_scores)` → `template.total_score`；
- `services.py:930-943` 的**卷卡总分一致性校验**：答题卡总分 ≠ 试卷总分时报
  `TOTAL_SCORE_MISMATCH`（blocking）。

于是批量把每空分值从 2 改成 3，会直接把一张已经绑定好的卡变成"总分不一致"。

**必须先回答**：统一设置的分值是
- **A 只做版面标注**（保持当前语义）→ UI 上必须写明"仅影响卷面标注与总分，不影响自动判分"；
- **B 同时驱动判分**（要改 `judge.py` 按权重给分，并把 `blank_scores` 从模板传进判分链路）→ 另一档工作量，不要混在这轮里。

### ② 统一设置是"一次性写入"还是"持续约束"

`sheet.sections` 是 JSON 快照，没有"继承的全局默认值"概念。两种做法：
- **A 一次性套用**（推荐）：按钮「应用到全部小题」，把当前值刷进每个 item，之后各题仍可单独改；
- **B 全局默认 + 逐题覆盖**：要新增 `fill_defaults` 字段并在 `_normalize_fill_item` 里做合并，语义复杂、迁移成本高。

### ③ 每行高度怎么表达（单自由度陷阱）

现有公式 `line_h = font_mm × ratio + 1.6`，`padding 1.6mm` 是硬编码常量。
"每行高度(mm)" 和 "行距倍数" 是**同一个自由度的两种写法**，同时暴露会打架。三选一：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | UI 只暴露「每行高度 mm」，内部换算成 `fill_line_spacing` 存储 | 老师直观，需处理换算与取整 |
| B | UI 暴露「行距倍数」，标签写"≈ X mm" | 改动最小，老师仍要心算 |
| C | 新增 `fill_line_height_mm` 字段，公式改成 `max(ratio·font, 直接值)` | 两个参数同时生效，最容易出诡异结果，**不建议** |

### ④ 行距下限必须与切图联动（不能沿用 1.6）

切图侧：`omr/crops.py:59/62` 纵向留白 `ASCENT 7.6 + DESCENT 0.4 = 8.0mm`，
`_rect_of_fill_line()` 以行为单位按 8.0mm 高切片。

代入 10.5pt（font_mm≈3.70）：

| fill_line_spacing | 行高 | 与切图高 8.0mm 的关系 |
|---|---|---|
| 1.6（当前下限） | 7.52mm | **重叠 0.48mm**，切到相邻行笔迹 |
| 2.3（默认） | 10.11mm | 白带 2.11mm ✓ |
| 4.0（上限） | 16.4mm | 白带 8.4mm，浪费纸 |

**结论：安全下限应满足 `line_h ≥ 8.0 + 2.0`，即 10.5pt 下 ratio ≥ 2.27。**
所以字面实现"新增行高控制"时，下限必须由 `base_font_pt` 推导，不能写死 1.6。
`crops.py:163-166` 的注释也承认这个约束，但它把最小值当成 1.6，与自身算法矛盾——这是既有缺陷，顺手修。

### ⑤ 改行高 = 改几何 = 旧卡必须升版本

`models.py:222` 写明 `version` 只增不改。行高变了，`layout_json` 里所有填空行的
`y_mm` 全部变，已打印的卡与新卡不能混用同一版本。所以：
- 保存成功要递增 `version`、旧版本置 `DEPRECATED`；
- 历史扫描卡的切图是**落库产物**，改算法不会重算，需要
  `manage.py backfill_subjective_crops --assignment <id> --force`。
